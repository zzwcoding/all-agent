## 取舍

- **探针机判面定为「草案域 YAML 全文+细稿两节」，对照表只给人看不进机判**：票面裁决的机判核心是「关键词表×（草案 ID 集+细稿问题节）双向核对」；落成子串级探针时，对照表若进扫描面，负变体就得连对照表一并造伪——对照表是覆盖的登记面不是落点面，进机判会让「登记了但没落」假绿。登记面与判定面分离，负例才立得住。
- **负变体共用草案目录、只注细稿**：AC2 语义是「细稿漏一个关键词落点且草案无对应」——含糊词本就不该进草案（questioning-guide §6 的机判推论：含糊词不进结构，负例才可构造），故草案无「及时处理」是正例性质的成立前提，负变体只需注入细稿漏覆盖。负变体头注把注入说明放头部（探针不扫头部），既可追溯又不污染判定面。
- **行为/主体/查询统计不产空壳文件**：M2/M5/M7 缺证据走 omittedModels 带理由豁免而非空 behaviors/actors 文件——空壳过不了票 13 结构性必填闸，也不该过（「不发明素材里没有的语义」的 manifest 面）；挂起动作在细稿留痕、豁免理由写缺什么，Owner 答复后按条补文件撤豁免。
- **docs/requirements/ 放落位示例而非留空目录**：git 不跟踪空目录，且布局模式无实跑载体=空登记；放 inspect-细稿.md 示例（golden 仍在 fixtures，头注声明主从）让归档闸新模式当场可验，也给票 31/32 的落位形态立先例。
- **草案域用「设备巡检管理」而 AGG 前缀取 INSPECT**：票面指定中性域；域 id 取 inspect（prefix2model 前缀纪律 AGG-{域}-{NNN}），对照表与草案元素 ID 对得上。

## 坑

- **YAML 头部注释引用含糊词原文会打穿覆盖探针负例**：初版 m3/glossary/m1 头注写了「『及时处理』『相关部门』不硬化成规则」之类的纪律说明——字面上这把关键词放进了草案 YAML 全文，探针会判「草案已覆盖」，负变体永远绿不了。修正：草案 YAML（含注释）一律不引用含糊词原文，纪律表述改用转述（「时限口径、责任归属」）。教训：子串级机判的排除面（注释/描述/对照表）都要按判定面同等级看待，写「本文件不含 X」本身就是含 X。
- **fixture_run 的 --fixtures-dir 是出厂集层的上级**：调试时传 fixtures/requirement-explorer 会把 input/ 当成一个出厂集报「缺 assertions.json」；该参数期待 fixtures/ 目录本身（CI 用法），单套调试直接跑全量后过滤。
- **改负变体时只删了 Q2 标题漏删字段行**：Edit 匹配块横跨标题+正文时容易留孤儿（字段行挂到上一问），三字段计数断言（问数==字段行数）恰好能抓这类畸形——负变体自身的结构完整性没有断言兜底，靠人工复读发现；记入此处备查。
- **schema 依赖经符号链接解析的目录层级**：expected-output/schema → ../../../ontology/schema（与 db-reverse 同款三层回退），放错层级 schema_check 会报「缺 schema 文档」；新出厂集抄此手法时先 `ls -la` 验链接再跑闸。
