## 取舍

1. **sync 只重写有漂移的 skill，已一致的整目录跳过**：票面 L0 是「先清后拷」，对有漂移的 skill 照旧整目录 rmtree+copytree；但零漂移 skill 再拷一遍只会白改 mtime。跳过使「连跑两次第二次全 skip」成为行为级幂等（单测断言 mtime_ns 不变），也让实机日常跑 sync 无副作用。删除面仍在 `<安装位>/<skill名>/` 目录本身，与 L0 无出入。
2. **单位置参数手工分词，不用 argparse 双位置**：首版按 `command(nargs="?", choices=("sync",))+skills(nargs="*")` 建模，绿相暴露 argparse 坑——`--check alpha` 把 skill 名错喂给命令槽触发 SystemExit（argparse 的 usage error 退出码恰好也是 2，但语义错且单测直接崩出）。改为单个 `words` 位置参数收全部词、main 里手工解释（首词=sync 则其余为 skill 名；--check 模式下全部按 skill 名解释），比 choices 更健壮，--help 语义不变。
3. **退出码对齐仓内约定**（graph_index/schema_check 同款）：0 一致/同步成功；1 有漂移（含 sync 后复检仍漂移的防御分支——正常不可达，报「脚本 bug 请回报」）；2 用法/配置错误（argparse 自身错误也落 2，天然对齐）。--check 人读输出里差异行用 `类型\tskill/相对路径` 逐行机读（missing/modified/extra），汇总行带分型计数；`--json` 全量报告给未来 pre-commit 钩子。
4. **文件对照不用 filecmp**：filecmp.cmp 有进程内缓存（按 size+mtime 键），先清后拷重建文件在极端时序下可能吃到陈旧缓存假绿；改为 stat 大小预筛+字节全量对照，确定性无缓存。
5. **--check 对「安装位根不存在」报全 missing 而非 rc=2**：没装过是合法漂移态（检查器该说清缺什么），配置错误只留给正本根缺失/空、未知/非法 skill 名、安装位根=正本根这类「脚本无法继续」的情形。
6. **不进 ci.sh 四闸照票面执行**：安装位是仓外环境状态，单测面已把 sync/--check 逻辑全量覆盖（借环境变量注入），CI 保持只管仓内 git 内容；tools/ 布局 pattern `*.py` 天然收编两个新文件，归档闸零改表。

## 坑

- **argparse「可选位置+choices」吃掉 --check 的 skill 名**：`--check alpha` 在解析后剩余位置串会先匹配命令槽，`alpha` 不在 choices 里直接 SystemExit(2)——单测红相伪装成「退出码正确」的假象，靠断言 stderr 内容才钉死。凡「子命令+可变参数」形态，argparse 双位置建模都不可靠。
- **macOS resolve 掉 /var → /private/var**：安装位根解析带 `.resolve()`，单测期望值必须同样 resolve 后再比（首绿相 1 条 failure 即此）。
- **`"references" / "stray.tmp"` 是 str/str**：手滑把两个字符串用 `/` 拼接（Path 语法误用到字面量上），单测自身 TypeError——红绿循环里第三相（修测试笔误）也算留痕。
