# 施工日志 45 · 人审闸审记状态机（tools/review_gate.py 四动作 + 哈希锚定）

## 做了什么

1. **tools/review_gate.py 四动作 CLI**（纯标准库，hashlib/subprocess，零外部依赖）：
   - `init`：建审记旁档骨架 `{target, created, records:[]}`；已存在提示不重建（exit 0），
     已存在但不可解析（损坏）拒绝重建 exit 1（design §3.4 #2：审记可以缺，不可以编）。
   - `approve`：追加 verdict=已审 记录 `{target, reviewedCommit(git rev-parse HEAD),
     reviewedSha256(现算), verdict, checkpoints[], notes, reviewedBy, date}`；审记缺席
     自动落头；既有审记损坏拒绝追加（exit 1）、既有记录违约拒绝追加（exit 2）——追加
     不能"顺手修史"。
   - `reject`：verdict=打回，`--routing` 强制（缺失/空白 exit 2，报错带「打回必须当场
     开单：业务错道→提案池 / 工程错道→tickets/NN」分道指引，裁决点 6）；打回记录带
     routing 字段落笔。
   - `verify`：判定树全按 specs/review_gate.md 退出码表——绿 0 / 失效·缺失·损坏·打回态
     1 / 配置错 2；只读，任何红不重建审记；`--json` 机读面（status/exitCode/recordsCount/
     最新记录）。
   - `--review-dir` 全动作可注入（缺省 exports/reviews/，裁决点 4 落点）——出厂集与单测
     在 exports 之外跑状态链全靠它。
2. **reviewedBy 随票裁决**（design 开放问题③，票面"施工时确认并写进 specs"）：reviewedBy
   = `git config user.name`（以目标所在目录向上找仓），取不到写 `"unknown"` + stderr 提示；
   reviewedCommit 同路（`git rev-parse HEAD`，非仓/git 缺席 → `"unknown"`，sha256 锚定
   不受影响）。已写进 specs/review_gate.md 边界语义 #1。本仓实测 git 身份 = divh。
3. **审记损坏两档机判**（票面 AC2a/AC2b 钉 exit 2 与 design §3.4"损坏按待人审"的合成
   裁决，见下取舍 2）：不可解析/头部结构坏 = 丢失级损坏 → exit 1 按待人审不重建；
   可解析但违约（缺必备字段/verdict 非法值/打回缺 routing/sha256 非 hex）→ exit 2
   fail loud 附逐条脏点定位，不跳过脏记录取旧值（审记整体不可信）。
4. **tools/test_review_gate.py 36 例单测**（tempfile 全覆盖）：init 骨架/幂等不重建/损坏
   拒重建/目标缺失；approve 绿链/记录字段真值（独立 git 取值对照，零共享被测逻辑）/
   git 降级三路（非仓目标 reviewedCommit=unknown、`_git` 注入全失败双 unknown、仅缺
   user.name 单降级）/自动落头/checkpoints 解析/损坏与违约拒绝追加；reject 缺 routing
   exit 2（含 argparse 不接管的原委，见坑 1）/带 routing 落记录/打回后 verify 红/重审
   恢复绿；verify 失效（AC1）/失效后重审恢复绿且旧记录保留可查（AC3b）/无审记不重建/
   损坏待人审/空记录待人审/schema 违约逐字段 exit 2/`--json` 面；路径解析。全绿，
   仓总单测 528→564（skipped=3 与基线同）。
5. **fixtures/review-gate/ 出厂集**（16/16 中第 16 套）：静态预置审记旁档五态
   （records/ 合法已审·哈希锚定=靶件真实 SHA256·verify 绿；records-stale/ 锚定≠现算·
   失效红；records-corrupt/ 不可解析·待人审红；records-missing-field/ 缺 reviewedSha256·
   exit 2；records-badverdict/ verdict=「已合入」·exit 2）+ 审记靶件
   targets/sample-artifact.md（内容固定逐字节稳定）。断言 12 条：读面三条直接跑
   （cmd-succeeds/cmd-fails），写面三条 python -c 探针在 tempfile 临时 git 仓跑
   （票 23/25/42 手法先例）——RG-AC2（三负变体逐一钉 exit 2）、RG-AC3（init→approve
   →verify 绿→手改目标字节 verify 红→重审恢复绿且旧审记保留，锚定真 HEAD 真 sha256）、

6. **specs/review_gate.md**（与实现互为镜像）：CLI 契约、审记格式 JSON 样例 + 字段表、

   覆盖/目标绑定=preserve 文件名+哈希/打回开单/published 只预留/不进 ci.sh）、出厂集
   断言表与单测覆盖面对照。

   状态机判面在 review_gate.py verify，闸不重复判定），producer=review_gate.py，

## 取舍（口径账）

1. **exports/reviews/ 本票不建骨架样例**：票面交接包"可建可不建"，实查 repo-layout.json
   exports 目录 patterns 只收 mcp/devkit/skillpkg 三类——建了任何文件（含 .gitkeep）都会
   被归档闸判 pattern-mismatch 红，而 repo-layout.json 不在本票 Touches。且审记样例已在
   fixtures/review-gate/records*/ 静态预置（归档闸 layout 表 fixtures 类 `*/**` 全收），
   格式冻结的真源齐备，票 46 接线时 exports/reviews/ 随首条真实审记诞生（layout 表同票
   扩 patterns）。这是"样例放哪"的显式裁决，非遗漏。
2. **审记损坏分两档**（不可解析=exit 1 待人审；可解析但违约=exit 2 配置错）：主窗口
   防踩坑 #1 写"无审记/审记损坏 exit 1"，票面 AC 表（断言真源，协议第 8 条）钉 AC2a
   缺字段/AC2b verdict 非法 = exit 2——两文面按"损坏"的损坏程度分层各得其所：解析不了
   的按丢失处理（宁多审一次，design §3.4 #2），解析得了但违约的是确定性配置错（fail
   loud 定位脏点）。specs/review_gate.md 退出码表已把这条合成裁决成文。
3. **verify 不做 target 字段与实参的路径机判**：旁档文件名即绑定面 + 哈希锚定兜底
   （内容不同必红）。不做路径机判的原因：预置审记要可移植（fixture 目录绝对路径随机器
   变）、macOS tempfile /private/var 符号解析等形态会造出假红；approve 落笔的 target
   自述保留人工可查价值。
4. **reject 的 --routing 不交给 argparse required**：argparse 裸缺参提示没有「打回必须
   当场开单」语义，改为 cmd_reject 内强制（exit 2 + 分道指引报错），语义与可测性双收。
5. **审记缺席时 approve/reject 自动落头**：init 是显式建骨架动作，但状态机不变量是
   "追加式留痕"——首条真实裁决记录本身就是历史起点，强制先 init 只是仪式；自动落头
   只写结构头，不伪造任何裁决，与"审记可以缺，不可以编"相容。
6. **fixtures/l5-scoring/out/ 两文件被我跑 CI 再生弄脏后还原**（git checkout）：该目录
   是票 42 遗留的"出厂集探针产物入库且带时间戳"形态，任何 fixture_run 都会改写其字节
   （既有行为，非本票引入）；本票保持 Touches 面干净故还原，后续谁跑 CI 谁见同样脏。

## 坑

1. **argparse subparser 的 required 参数会抢走语义报错**：`--routing required=True` 时
   缺参在 argparse 层 SystemExit(2)，自定义「打回必须当场开单」报错永远打不出来——
   带语义的必参校验要放进动作函数，argparse 只管形态。
2. **`git config user.name` 在非仓目录也会成功**（回落全局 ~/.gitconfig）：tempfile 靶件
   的"git 缺席"实测只降级 reviewedCommit，reviewedBy 仍取到全局身份——降级测试不能想
   当然钉"双 unknown"，要么独立取期望值对照（本票做法：测试侧 expected_git 零共享），
   要么注入 `_git` 失败钉单点。
3. **出厂集写面断言必须零仓库写入**：fixture_run 收集 `git ls-files` 全集（含 untracked），
   探针在 fixture 目录内落任何文件都会被归档闸红；本票探针全部 tempfile + finally 自清。
   反例在档：fixtures/l5-scoring/out/（票 42）探针产物直接入库，每跑一次 CI 字节必变
   （取舍 6）。
4. **python -c 探针塞进 assertions.json 时**，JSON 字符串里的 `\n` 是真换行、代码内
   字符串再嵌套引号只可用单引号——l5-scoring 同款，复制粘贴断言前先跑一遍再入库。
