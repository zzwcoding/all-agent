## 取舍

- **docs/meta/ 挂进 docs 条目而非独立条目**：archive_check 的布局核对按「顶层目录」查表（`rel.partition("/")` 取 top 再 by_path.get(top)），`path: "docs/meta"` 的独立条目是**永远查不到的死配置**；且 fnmatch 的 `*` 可跨 `/`，docs 现行 `*.md` 实际放行了 reviews/ walkthrough/ 全部子目录——故登记为 docs 条目内 `meta/*.md`、`meta/*.json`（与 adr/*.md 先例同形），死条目不加。
- **八问常量表内置而非机读 assertions**（L0 裁决）：断言里问句与期望埋在 `python3 -c` 探针 cmd 字符串里，机读要再写一层脆弱解析（过度工程）；内置表 + 头注指认真源 + modules.md 同步注记，三处对齐够用。
- **硬闸 SKIPPED 判 DEGRADED 仍退出 0**：票面 AC4 只要求「缺席降级不崩」，未要求判死；探针是采集器不是闸，闸缺席是环境降级不是体检红，但结论行如实报 DEGRADED 不冒充 PASS——诚实呈现与退出码契约两全。
- **CORE 期望漂移记信息红而非硬红**：探针 3 按裁决是信息项；冻结期望的真源在出厂断言（CORE-01–08 cmd 断言已把漂移判死），探针重复判死=把信息项升格成第二闸，违背「判定归各闸」红线；漂移在报告里以 **漂移** 针标注即可。
- **stdout 用 sys.stdout.write 不用 print**：print 追加换行使 stdout 输出与 --out 落盘差一个空行；确定性要求「同仓快照重跑一致」，收窄到字节级更省心。
- **proposal_check 传绝对路径 + 假 runner 全兜**：真仓跑时 pdir 用绝对路径免 cwd 歧义；测试侧该调用被假 runner 截胡，不触真工具。

## 坑

- **布局表的目录匹配是顶层的**：差点照票面字面加 `path: "docs/meta"` 独立条目——写完后回读 archive_check.check_layout 才发现按顶层查表，该条目永远不会被消费；fnmatch `*` 跨 `/` 的语义也让「docs 的 *.md 放行了所有子目录 md」这个既成事实显形（reviews/ walkthrough/ 就是这么过的闸）。登记子目录产物=给顶层条目加模式。
- **schema_check 的 `files` 字段是 int**：首版探针 2 对它调 `len()` 抛 TypeError，被 collect_all 兜底成「采集异常降级 SKIPPED」——**AC4 的兜底机制第一枪接住的正是一个探针自己的 bug**（真仓冒烟 DEGRADED 当场暴露，非静默）。修为 `isinstance(files, int)` 判型取值。
- **测试双 TestCase 继承**：最初把 FakeRepo 写成 TestCase 混入 `class T(unittest.TestCase, FakeRepo)`，unittest 对多 TestCase 基类行为不可靠；改 FakeRepo 为普通类、测试类 setUp/tearDown 显式建毁。
- **CI 测试里的真子进程 cwd**：CLI 测试传假 root 时若不注入 runner，main 会拿真 runner 在假仓跑 `tools/fixture_run.py`（不存在）→ 全 SKIPPED 假绿；main 加 `runner` 注入口后测试面干净（这也让「CLI 层的 DEGRADED/FAIL 落盘」可注入复现）。
