## 取舍（口径账）

- **自建最小节点索引（本票最大取舍）**：二级名称解析需要全量候选面，graph_index 无全量列举能力、逐 ID 试探不可行；core 内 PyYAML 直读域文件建 id/name/alias/属性标签索引**仅限解析面**，图遍历仍全部走 graph_index 子进程（图拓扑单一读者不破）。代价：解析面与图索引的节点口径可能漂移（同 ID 重复定义取先出现者，两读者规则一致；schema_check 才管冲突裁决）。
- **camp 判定先阵营后存在性**：SCR-BOHAI-01 在真域不存在——先按前缀判 MU camp=build-contract 即拒（refused_out_of_surface，裁决书的期望形态），不是「未找到」；实现取此序并在裁决里如实带 `anchor_exists:false`（阵营说明不因节点缺位而撒谎）。先查存在性再查 camp 的等价实现按主窗口口径亦可接受，两者对八问的 status 相同。
- **出厂集拒答断言用 cmd-fails（对防踩坑 5 字面的偏差，记偏差账）**：L1 提示「CORE- 断言 cmd-succeeds+outputContains」，但票面 CLI 契约（L0）规定拒答退出码 1（拒答也是有效裁决），cmd-succeeds 必红；故 answered 五问=cmd-succeeds、refused 三问（Q4/Q5/Q8）=cmd-fails，outputContains 同样钉 status 与关键 ID。票面 > 提示字面。
- **多候选=answered+ambiguous，不设第五种 status**：Q1「日产量」词面可命中行为/出口名（查询单井日产量），Q6「有效产量」天然两支（GLS-BOHAI-003 术语+RULE-BOHAI-019 剔检支）——走查的「唯一命中」靠人工语义对齐，core 的确定性骨架只能给词面证据的排序候选集；**在候选中挑承载者是语义工序=skill 的事**（提纯边界的正面体现）。status 枚举照契约不扩。
- **citations 装配口径收窄**：citations = hits ∪ closure1(hits) ∪ impact(hits)（hops≤2）∩（camp=business-core ∩ 模型面 ∈ OBJECT/BEHAVIOR/RULE/REPORT/GLOSSARY）。PERM/ROLE/ACTOR/FLOW 不入 citations（Q7 否则 60+ ID 全是权限噪声），但 --impact 全集可经 scaffold_commands 逐条复现——证据集收窄不藏证据。GLS 命中加扫 impact(closure 目标)，使承载规则（RULE-BOHAI-019）可达，ac7 参照答案 ID 集被超集覆盖。
- **缺件分层是机械面**：R2 缺件按查询/对象字段/行为规则三层核对，层判定=2-gram 字面交集（桶油增产成本对全域零交集→三层全「未建（待 Owner 提案补建）」）；近邻指路只在有字面交集时给（至多 2、标「非所问」）——不硬凑近邻，把「桶油成本的分子缺投入字段」这类语义归因留给 skill 成稿。
- **t4 头前缀层的词面噪声如实呈现**：Q6 会把 AGG-BOHAI-005（属性标签「有效期…」头部共「有效」）列进候选末位——这是词面证据的诚实登记（层低、排序后、ambiguous 提示锚定），不是命中担保；若要压噪只能引入语义判断，越出 core 边界。

## 坑

- **impact 方向的反直觉**：`appliedRules`（行为引用规则）是依赖方向，impact 反向走不到；真域 RULE-BOHAI-002 之所以在 impact(AGG-BOHAI-002) 里是经 `reusedBy`（规则登记复用方=依赖方）两跳可达。demo 夹具初版只建 appliedRules，RULE 不可达误判为 core 缺陷——夹具补 `reusedBy: [BH-…]` 镜像真域形态后绿。写合成域先想清「谁是依赖方」。
- **合成域的 schema 探测半径**：resolve 手法是 target/schema 与 target.parent/schema 双探——/tmp 域的兄弟目录放 schema 才符合「域旁 schema 链接」；测试里 config-error 用例特意用隔一级的目录，避免蹭到上级 schema 造成假阴性。
- **fixture 断言钉 JSON 串**：outputContains 钉 `"status": "refused_missing"` 带引号冒号全串（indent=2 输出形态），只钉值字符串会误配到 reason 散文。
