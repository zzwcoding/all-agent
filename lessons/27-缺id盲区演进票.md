## 取舍

- **无 id 元素只报「缺 id」一行，不叠加其余必填字段**：备选是对无 id 字典把所属前缀必填集全量核对（M2 会连报缺 ownerEntity 等），但 M1/M5/M7 一文件多前缀集（AGG-/DICT-/ASSOC-；ACTOR-/ROLE-/PERM-）在缺 id 时无法判定归属前缀，全量报会张冠李戴；且无 id 修好后下一跑既有逐字段闸自然补齐其余红——红因纯净、每行可指认，沿票 13「缺什么报什么」精神。
- **matched 元素仍走原 `collect_elements`（递归全文件扫描）而非收进集合枚举**：票 27 的盲区只在「无 id 一侧」，有 id 一侧的既有行为（含一致性对四处消费 collect_elements）零扰动是硬红线；嵌套不进**枚举**由 iter_collection_items 只扫顶层列表天然保证，collect_elements 改面=无谓扩大爆炸半径。
- **错前缀 id（集合里挂别家模型 ID）判缺身份而非放行**：备选是只认「字面无 id 键」为缺 id，但旧版该形态恰被空壳守卫误吞（红是对的、因是错的），收窄空壳后若放行反而制造新逃逸；判缺身份让红因从「空壳」迁移为「不判回本模型注册前缀」，专测钉死。
- **空壳报文重写但保留「空壳文件」字样**：REQ-AC3b 断言钉了 `["required-field", "空壳文件", "GLS"]`——收窄后的报文仍含三针，**既有断言零改动**（交接包防踩坑 #4 的复核结论：红因对纯空集合形态不迁移，只有「集合有字典」的形态才从空壳迁为逐元素）。
- **AC3/AC4 不立新断言**：出厂断言面 outputContains 只能断「有」不能断「无」，零扰动与不回退本质是「既有绿/红断言继续成立」，重复立行=假覆盖；单测面用 `assertEqual(rows, [])` 把「嵌套字典无 id 不报」钉在函数级。

## 坑

- **新测试基座的机读表要成对换**：ElementIdEnumeration 最初只覆写 registry 沿用 ReqBase 的 REQ_DEPS，其 edges 引用未注册的 M7 → deps-registry-conflict 一条假红。教训：自管基座类凡是复制 setUp 的，覆写面必须覆盖「互相一致性核对」的**两**张表（registry 与 deps），漏一张就被闸自己抓。
- **断言针的搜索面是 stdout 全文不是 message 字段**：复核 REQ-AC3b 时先在 Python 里只对 `violations[0]["message"]` 找 `required-field` 误判「断言针缺失」——`required-field` 是 kind 在人读输出的行前缀 `[L1][required-field]`，fixture_run 的 outputContains 搜的是 stdout+stderr 全文。复核断言要按断言器真实口径取样，不按自己想当然的字段。
- **`schema` 符号链接目录会混进 glob**：`fixtures/schema_check/ontology/*/` 展开含指向仓内 ontology/schema 的符号链接（票 13 立的单一真源机制），对它跑 schema_check 得到 0 域 0 文件的全过报告，before/after diff 前要显式排除，否则 diff 噪音盖住真差异。
