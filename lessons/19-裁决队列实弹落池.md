## 取舍（口径账）

1. **accepted 回填提案以 modify 形态登记**：票 10/16/17 闭环的都是「往无中生有」（GLS 术语位/闸/Golden Q 问句），proposal_check 对 add 的判定是「靶必须不在域」——而闭环已执行、元素已在真域，照历史形态写 add 必红。取舍：accepted 提案以裁决在真域的落点元素为 modify 靶（GLS-BOHAI-006/009/010/001/002），正文首节固定「裁决落痕（回填登记）」写明裁决出处与 commit，声明非待执行草案。这是对检查器 target 判定没有 status 豁免的如实适配，不是语义造假——裁决已发生，提案登记的是裁决本身。
2. **落池量 31 份，超票面预估 15–22**：L0 预估在盘点前做出；实盘后 (c) 部分译 4 项、规则 6/11、清单 (b) 与 (a) 的非重合项都要么立提案要么给不立理由——「素材清单全覆盖零遗漏」是 AC2 硬约束，宁全勿漏。超量部分每份都有真实素材依据（防踩坑 2：判无可判的宁缺毋滥，见取舍 5）。
3. **合并同靶三处**：D8（油田提升）并入无源实体族提案（同一裁决束：五个无源实体怎么建）；D13（使用边界）与指标 10 基线参数并案（同靶 RULE-BOHAI-018、同为「这口径能不能用」）；D9（layerSplit 格式）与配注合格率分母残留并案（同属性面、同 Owner 裁决）。合并避免同靶多案互搏，也符合「一提案一主信号、附带信号进正文」的归一纪律。
4. **占位提案手法**：提取件二 8 条/MU/规则 6/规则 11 四案素材在仓外或不存在——按「C 级证据先转录落盘才可作依据」不硬译，提案只立号位与可二选一的裁决点（给素材则建/明确不给则 rejected 归档），rationale 照实写「待 Owner」。这样队列不留悬空「待 Owner」字样，每条都有归宿。
5. **清单外 8 项不立提案**（对账表 B1–B8）：affectedOutput 口径、躺井限语境、存水率指标化、全译行内实现层注记、低烈度 3 条、wellRef 双表示、行为颗粒度/roleRef 归位——均未进 L0 三真源清单或自判不单列（dirty-signs 低烈度）、须过影响分析（键变更）。逐条给理由落对账表，不静默吞。
6. **open 提案的表达式留白写法**：判据待 Owner 的规则草案 expression 落「待 Owner（……后落表达式）」+ 判定形态注释，而不是编一个像样的公式——「不发明语义」在提案面同样适用；草案 YAML 一律标注「进仓走 MR，非已定稿本体」。

2. **accepted 提案撞 add 判定**（见取舍 1）：起草时若照历史「新增术语」写 add，proposal_check 会红「add 的靶元素在真域已存在」——这不是工具错，是「已执行的 add」在池里的形态问题；回填登记一律用 modify+裁决落痕节。
3. **zsh 下 `===XXX===` 作 echo 参数**会被当 glob/命令解析（两次报 `== not found`），与施工无关但浪费往返——分隔输出用 `echo "---xxx---"` 带引号。

## 走查小结（proposal-pool 工序端到端实测反馈——skill 迭代输入，写真话）

**顺的地方**
- 四步工序（受理→归一→预检→落盘）对「批量起草」场景无摩擦：31 份提案一气呵成，机检四类一次全过，说明字段定义（proposal-format §2）与工具实现零漂移——照规范写就是绿的，这是格式规范「一字不差对齐」策略的直接红利。
- 证据等级（A 机读锚点/B 人读文档/C 仓外先转录）在本票全部用上且判断无歧义：D 项引 dirty-signs（B）、已建元素引模型 YAML（A）、提取件二挡在 C 级门外——等级规则把「不硬译」从自觉变成了机械可判。
- 「target 存在性照真域」的判定逼出了正确 change 选择：本票没有一处凭印象写 add/modify，全部 grep 核实——闸在这类细节上比人可靠。

**卡的地方**
- **已闭环提案没有合法的 add 形态**（取舍 1）：票 18 工序与格式规范都没写「裁决已执行的 add 怎么回填登记」，proposal_check 的 target 检查也不豁免 accepted——回填场景是本票新踩出来的，规范该补一节（建议 proposal-format §4 增「回填登记：已执行 add 以 modify+裁决落痕节登记」条款，或在工具给 accepted 豁免 add 存在性判定——前者零代码改动，推荐前者）。
- **占位提案的 ruleType 没有合法枚举**：提取件二/规则 6/规则 11 占位草案里 `ruleType: 待定`——M3 规则的 ruleType 枚举是本体 schema 的事，但提案草案写非枚举值若将来被某闸扫到会红；本票机检不查正文所以没爆，属侥幸。建议 signal-normalization §4 增一句「草案内占位值用注释而非字段值承载」。
- **kind 五类对「批次占位/素材征集」类信号偏窄**：MU/提取件二提案本质是「向 Owner 要素材」，最贴近的是疑点/交互，但都不是精确命中——五类枚举是否够用，建议元循环体检（F14）收运行数据再裁。

**规范建议（给 skill 迭代）**
1. proposal-format.md 补「回填登记」条款（同取舍 1）；
2. signal-normalization.md §4 补「占位值进注释不进字段值」；
3. skill 工序第 2 步「change 按真域核对」建议补半句「已执行闭环的回填提案以落点元素 modify 登记」——本次是我自己绕出来的，下一个窗口不该再绕一遍。
