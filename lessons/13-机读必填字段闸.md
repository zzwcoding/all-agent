## 取舍

1. **必填表落 registry 每模型字段，不建独立机读文件**：票面给的两个选项里 registry 是优先项；registry 已是「模型目录页」（camp/profiles/dependsOn/lockedFields），必填集是同一目录页的又一列，独立文件反而多一份一致性核对负担。registry description 与 schema.md §13 已同步登记。
2. **文件名错挂的文件跳过必填闸**：gls-ac4 形态下（GLS 内容挂 m1 文件名），若照常按 model_type=M1 收元素会得到「M1 空壳」杂音红因——内容与模型的锚已断，锚定面归 filename-mismatch 管辖。这让 ac4/gls-ac4 老负变体红因保持纯净（票面防踩坑 5「尽量保持」）。单测 RequiredFields.test_filename_mismatch_skips_required_gate 钉死。
3. **M2 appliedRules/requiredPermissions 入集而 preconditions 不入**：票面口径是「引用扫描依赖、缺失即静默跳过」——appliedRules/requiredPermissions 是 refKeys 成员（缺失=该行为的规则/权限引用面静默消失），preconditions 是纯业务面（票面明示「preconditions 等」不在本票）。requiredPermissions 键必填与票 11 §14 P2「行为侧留空不判红」不冲突：闸只查键在场，空列表合法（bohai 质检行为即空列表）。
4. **omittedModels 在场判定按注册文件名**：ac2 坏 YAML 域的 m2 文件解析失败，按内容判定会连 M2 一起报缺文件（7 条杂音）；按文件名判定则「文件建了=在场」，schema 错误留给 L1 不重复追责。
5. **豁免条目缺 reason = 无效豁免照红**：「带理由豁免」是票面原文；reason 空串的条目不构成豁免，缺文件照样红——防止用空理由把反向闸洗成永远绿。引用未注册模型/条目缺 model 键单独 L1 红（错别字静默失效的防御）。
6. **AC3 拆 REQ-AC3a/3b 两个变体**：票面 AC3 允许「缺 definition/source 与 terms:[] 各一或合并」——拆开每变体红因唯一（3a=缺 definition、3b=空壳），断言各自点名；assertions.json 两条共享 AC3 语义。
7. **check_citations 段式收紧为「纯数字段或大写开头段」**：首版段式允许 `001x` 这类混段，`QR-X-001x` 会被整段吞进 token；收紧后尾部粘字母不命中（单测钉死）。首段须全大写 ≥2 字符，`MENU-01`/`T-3`/`R5` 两段或单字母形态天然不命中。清单节切分从标记行首起（`## ` 记号归清单节，正文不含标记行）。
8. **单测基座（Base/ConsBase）预置 omittedModels**：反向闸会让「profile 启用却只加装部分模型文件」的既有测试基座翻红——基座 manifest 预置全模型豁免保住老测试语义，反向闸正负变体由新 MissingModelFile 专类用自管 manifest 覆盖，老 129 条零改动意图零翻红。
9. **注入样本附注不写真实 ID**：check_citations 是全文本扫描，样本里的解释文字若含 ID 形态 token 会被计入正文集（首版注入样本的附注写了 QR-BOHAI-999，清单注水差异被正文「自证」吃掉）——附注改纯散文描述，教训：给全扫描检具造样本时，元数据注释与数据同权。
