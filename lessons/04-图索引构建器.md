## 取舍

- **ref 扫描键取三源并集：refKeys ∪ *Ref/*Refs 后缀 ∪ model-deps.json edges 登记字段**。起因：M3.reusedBy（规则被哪些行为复用）只在 edges 登记、不在 refKeys、也不带 Ref 后缀，若只按 refKeys∪后缀扫描会漏掉整条「规则→复用行为」依赖通道，影响分析对规则变更就哑了（AC4 的「沿依赖白名单反向走」正是冲 edges 表说的）。图求完整，越白名单的裁决权仍在语义闸 schema_check。
- **graph_index 不读 model-registry.json、不校验 model_type**：ID 前缀已足以为节点定模型（schema.md §2「前缀即类型标签」），profile/阵营裁剪是消费方（semantic-service 检索面划界）的事，图保持单一职责；schema 合法性 L1–L4 全归 schema_check，两工具不重复判定。
- **同 ID 重复定义取先出现者、悬空引用照记不删**：图是派生物不是闸；冲突与悬空留给 schema_check 报，图只保证「重建结果=当前仓内容的机械投影」。
- **AC6 用「双目录对照」承载**：runner 的断言类型没有 stdout 不含检查，仓内容变化的确定性验证改为 base/modified 两份自管副本对照（改名+新增对象，同 ID 查询结果跟随内容走 + 新增 ID 在 base 报未找到）；「改后重建反映新内容」的进程内语义（同进程改文件→重建→输出变化）与「不落缓存文件」由单测 Ac6RebuildReflectsNewTruth 两条兜住。
- **未找到走 stderr、命中走 stdout**：机器消费一律 --json（found 布尔位）；人类面未找到是错误信号入 stderr，fixture_run 的 cmd-fails 断言合并两流故不受影响。

## 坑

- **PyYAML representer 按精确类型查表**：MDict/MList 这类 dict/list 子类直接 yaml.safe_dump 会 `RepresenterError: cannot represent an object`（SafeDumper 的 yaml_representers 是 dict 精确键查找，子类落空）。需要递归转纯 dict/list 再 dump（_plain 助手）；json.dumps 走 isinstance 反而没事。
- **「最近 ID 祖先」必须在扫 ref 键之前落锚**：walk 进映射先判定义键并注册节点、把锚更新为自身，再扫该映射的 ref 键——否则 reusedBy 这类「元素引用自身同级 ref」会挂到外层祖先，方向错。MU 菜单的 menuId 无登记前缀、不成节点，其 screenRef 因无锚而自然丢弃（屏幕本身由 SCR- 节点承载）。
- **手工数边数不可靠**：第一版断言按手推 29 条边写，实跑 27 条——差异正是 reusedBy 两条约定问题（见取舍第一条），用 dump 全部边对照后修正扫描规则再回到 29。教训：出厂集的固定数字断言必须以「语义推演+实跑核对」双确认，不能只靠推演。
- **测试基础设施的 DEPS 要镜像真实形态**：迷你域若把 reusedBy 塞进 refKeys，就永远踩不到「只在 edges 登记」的分支；DEPS 改成 refKeys 缺 reusedBy + edges 登记 reusedBy，并集路径才被单测覆盖。
