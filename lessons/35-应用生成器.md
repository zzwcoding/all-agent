## 取舍

- **生成器本体零子进程耦合，同源对账归出厂集**：设计裁决说「装配口径经 semantic_service_core/graph_index 子进程」，实装取其神——口径卡的命中 ID 集按结构装配（⊇ core 命中面），同源性由出厂集 AC1 探针跑 core 子进程对账机核；不把 core 解析结果烤进开发包，否则 core 行为演进（如票 25 camp 裁剪）会倒逼开发包再生成，防陈旧闸会从「域漂移检测」劣化成「core 漂移检测」。交接包逐节装配来源（①M1 YAML/②M7+M3/③M2/M3/④frontmatter）也全部零子进程，与 AC1「抽 1 问机核」分工一致。
- **「命中 ID=behaviorRef+objectRef+appliedRules」按交接包字面装不满 CORE-01**：CORE-01 冻结命中含 RULE-BOHAI-003/004，它们只经「ownerEntity=承载对象」通路可达——补第三支「承载对象关联规则」后 AC1 探针才真绿；这是把「口径四件套与 CORE 八问同源」当可机判命题倒推的装配面，非自由发挥（每条带 via 可追溯）。
- **负变体副本只带声明面文件（manifest+M1/M2/M7）**：M5/M6/GLS 非生成器输入，全量复制徒增同步面；README 注明范围与「固定输入不自动跟踪真域」的取舍。AC3 只判退出码与指认，不判副本内容新鲜度。
- **提案 frontmatter 解析失败=exit 2（响），status 非 open 或缺 target.element=跳过（轻）**：前者是提案池坏档必须拦（不静默吞）；后者是无法归属任何域的条目，跳过不进开发包，归属判定交 proposal_check 闸。
- **注源抽全行注释不抽行尾注释**：M1 属性行尾 `# [R5·A.4 样本 2026-08-28]` 若收进注源会把日期形态 token 带进开发包，直接违反零时间戳红线；且行尾注挂靠粒度会漏到下一元素。属性级注源不进开发包（属性约束面已足）。

## 坑

1. **--check 收文件路径还是目录**：交接包自查命令给的是 `--check exports/devkit/bohai/devkit.md`（文件），而比对对象是双文件——按「文件→取其目录；目录→原样」解析，双文件各自比对并逐文件报差异；篡改探针第一版只拷了 json 进 /tmp，--check 解析父目录后报「md 也不存在」，红是红了但红因不对——探针必须双文件在场只篡内容才验得出「逐字节比对」而非「缺件检测」。
2. **fixture 断言 cmd 里的 python -c 换行**：多行探针代码写在 JSON cmd 的双引号串里，内层字符串一律单引号、换行直接用真实 \n——照 CORE 探针先例；若内层出现双引号，shlex.split 切错参数且报错形态是 Usage 而非红因，极难排。
3. **domain_dirs 类发现手法这回不用**：mcp_manifest_gen 支持仓根扫全域，app_pack_gen 刻意单域出包（exports/devkit/<域>/ 天然按域分目录）——非域目录 exit 2 报「请传域目录」，比静默扫全域再猜输出目录深。
4. **M1 文件尾 `# 无 data_dictionaries：…` 说明注释**：无 [R<n> 标签，源标签过滤器自然滤掉，不会挂到紧随其后的 ASSOC-BOHAI-001——标签过滤（`\[R\d` 开头）兼做噪声闸，这条设计在先省了一次调试。
