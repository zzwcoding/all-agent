# 61 · smoke 量级快照断言陈旧（断契约形态不断快照数）

- 日期: 2026-09-24
- 角色: L0 主窗（票 66 施工窗，demo 信号即时清偿）
- 票: tickets/66-smoke量级快照断言陈旧修复.md
- 依据: 2026-09-24 全量 demo 实弹（Owner 在场）——smoke 客户端 8/9，U8 红
- 性质: 测试断言随活本体演进陈旧的第二例（与 lessons/58「管道掩码」同属「断言自己说谎」类坑）

## 做了什么

1. U8 断言从量级快照改形态契约：contains「【影响 --impact】」+「个受影响节点（依赖方）」+ BH-BOHAI-QueryWellDailyOutput + hops=1；not_contains「0 个受影响节点」非空守卫；量级（56/64/…）不再入断言。
2. fixtures/mcp-publisher/cases 对照单 U8 行同步去数字（注票 66 与 56→64 演进事实）。
3. 单测加 U8 契约钉（test_u9 同款先例）：形态 token 与非空守卫必须在位、「<数字> 个受影响节点」量级快照 token 不得入 expect_contains——修完即落闸，防回潮。
4. smoke 实跑 9/9（mcp 2.2.0/Python 3.11.15）+ venv 协议面单测 21/21；walkthrough step7 两处「56」为票 24 时点快照留痕不回改。

## 取舍

1. **断契约形态、不断量级快照**：影响集规模的「契约」是非空+含反向依赖行为+hops 形态，具体数字只是票 24 时点的实测值——把实测值抄进断言等于把「本体不再演进」写成前提。同型断言自查：U9「0 个下游节点」保留不动（AGG-BOHAI-001 无正向引用是结构事实，非快照量级——除非本体加正向边，那时红也是真信号）。
2. **不在 smoke 客户端里现算期望**（跑一遍 graph_index 对数）曾列候选：防陈旧最彻底，但让 smoke 客户端多一个子进程依赖、把「MCP 结果 vs 出厂集行为」的一致性断言变成「自己对自己」——一致性的真源应当是稳定契约，不是现场重算。否。
3. **walkthrough 历史留痕不回改**：日期快照的价值在于「当时真实如此」；篡改历史件对齐当下=毁审计链。陈旧说明记在本票与 commit message，不动原件。

## 坑（如实记，两条）

1. **「绿」会过期**：票 24 验收时 U8 真绿（当时真是 56），此后每个正常票往渤海域加规则/行为都在悄悄逼近红——没有任何闸盯「断言与现势图的一致性」，因为它不在 ci.sh 四闸里（SDK 免疫红线），而 smoke 只在 SDK 升级纪律时才跑。教训：**低频实弹面的快照断言是定时炸弹**，写的时候就要问「本体演进后它还成立吗」，答不了的直接断形态。
2. **demo 是唯一抓到它的面**：四闸全绿、体检 PASS、L5 全绿——全部确定性闸对「断言陈旧」这种元层面失明（它们检产品不检测试）。.Owner 在场的全量 demo 一跑就现形。教训：定期做一次**全链路实弹走查**（含 CI 外的发布侧组件），别让「四闸绿」替代「真的能用」。
