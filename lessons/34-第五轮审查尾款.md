## 取舍

- **probe 扩根的合并语义取「决定方快照」不取求和**：既有断言 `test_schema_red_exit1` 钉死 data.levels==SC_RED 精确值（现有断言零倒红线），且"任一红即红"语义下红方 levels 就是体检结论的依据——求和只会制造"修一半红减半"的暧昧读数。两跑逐目标明细进 data.runs，信息不丢。
- **patterns 排除只落域发现一处、不做全局目录名黑名单**：单域直跑（`schema_check ontology/patterns`）仍会检查——排除针对的是"仓根扫描时素材目录被误当域"，不是给目录名施法；归档闸 ontology-pattern 类与 pattern-library 出厂集才是模式件的结构纪律承载。
- **洗白探针判据走 source 锚点不走词面对照**：terms.md 的【Tn】编号 ↔ GLS source `terms.md#Tn` 是 doc-extractor 自己的锚点纪律（指导书 §1.4），锚点对照比 term 词面匹配窄且不可绕（改词不改锚=仍红）；status 含「禁用」也放行——Owner 升格后的条目不该被探针误伤。
- ** tickets/30 的整改注记写在票面 + 注释写在 YAML 行**：审查 P3 的"未标待 Owner"是产物瑕疵，机判面（file-contains 头部声明）零改动——YAML 行尾注释不进任何断言，参照产物语义不变。
- **收官报告 §6 追加条目带「票 34 追加」水印 + §9 注记行补再注**：§9 明文"§1–§8 原文一字未动"，直接静默插行会让该声明变成假话——追加水印 + 注记行说明追加范围，原文 #1–#9 一字未动。

## 坑

1. **fixture_run 不吃子目录当套件**：调试时 `--fixtures-dir fixtures/doc-extractor` 会把 input/expected-output/negative-variants 当三个套件全红——runner 的套件粒度是 fixtures/ 的直接子目录，单套件验证也得跑全量再 grep。
2. **python -c 多行探针进 JSON**：for/continue 塞不进分号一行流，用 JSON 字符串内 `\n` 转义 + shlex 双引号保留换行——python -c 收到完整多行脚本，实跑可过；模板占位符替换用 `.replace("{gl}",…)` 不用 `.format()`（{fixture_dir} 未提供会 KeyError，format 对未命名占位符零容忍）。
3. **schema 符号链接深度随目录层级变**：expected-output/datagov 是三级 `../../../`（且其自身 schema 链接其实是断的，靠上级 expected-output/schema 的链接 + schema_check 的 parent 回退才过闸——历史遗留，勿模仿）；negative-variants/t5-whitewashed 是四级 `../../../../`。链深错不报"链接坏"而报"没有 schema/"，排障先 resolve 链接。
4. **unittest -k 只匹配方法名不匹配 docstring**：验证修前红时 `-k latent` 匹配零条（"latent"只写在 docstring 里），改用 `-k gls_closure` 才命中——修前红两态验证各跑了一轮，别把"没跑到"当"跑过绿"。
5. **ssc 测试的相对路径溯源撞真仓**：FakeRepo 场景 target 传相对路径 `ontology/bohai` 时 find_ontology_root 会按 CWD 解析、在真仓里找到真 ontology 根——假 runner 罐头响应下结果碰巧不受影响，但新测试一律传 tempfile 绝对路径，不赌 CWD。
