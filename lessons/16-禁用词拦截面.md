## 取舍（口径账：三问三答，全有专测/出厂断言钉死）

- **禁用词表从哪来**：域内 GLS 文件的 `terms` 条目 `status` 含「禁用」子串 → 收 `term` + `aliases`。宽进严出：不枚举状态值（真源原文有「禁用（替代：×）」这类带括号形态，前缀子串判定最稳）；单测 `test_status_substring_wide_gate` 用「已禁用待复核」钉宽进面。
- **匹配面有多大**：所有字典中键**恰为** `name`/`alias` 的字符串值。不入面：`label`/`definition`/`notes` 等其他键（`test_matching_face_is_exactly_name_and_alias_keys` 函数级直测钉死七键只见二）、复数 `aliases` 键（那是禁用词表的**来源**字段不是匹配面——语义不同向：GLS 的 aliases 进表、非 GLS 元素的 alias 被扫）、非字符串值。防"悄悄放大成全字段"= 本票灵魂，负变体目录 `ban-ac4` 在出厂集层面再钉一道（description 提禁用词必须绿）。
- **GLS 会不会自匹配**：不会。禁用词表来自 GLS 条目的 `term` **值**，匹配面是 `name`/`alias` **键**——GLS 条目字段表（schema.md §11）以 `term`/`aliases` 承载词面，无 name/alias 键，天然不入面（`test_gls_own_terms_do_not_self_match` 专测 + `ban-ac4` 出厂正例双钉）。无需豁免逻辑；若未来 GLS schema 加 name/alias 键，此闸会开始自匹配——届时再议豁免，schema 演进账走 CHANGELOG。
- **作用域按域**：禁用词表=本域 GLS（术语表本来就按域组织，`domain: bohai`），A 域禁用词不拦 B 域 name——防未来多域时跨域污染误报。GLS 无文件的域（未建模/旧域）表为空、闸静默，零扰动。

## 坑

- **防误报护栏测试在 TDD 红相会"假绿"**：AC4 型测试（断言不出现某违规码）在闸缺位时天然通过——红相证据只有负变体的 5 FAIL + 1 ERROR。别把红相数对不上当 TDD 没做对：护栏测试的红绿价值在**未来**（有人放大匹配面/收窄 status 判定时翻红）。
- **cmd 断言挂真仓路径**：`BAN-AC3` 的 cmd 是 `python3 tools/schema_check.py ontology/bohai`（无 {fixture_dir}）——fixture_run 的 cmd cwd=仓根（`fx_dir.parents[1]`），相对路径直接可用；这是既有 runner 语义，不必改 fixture_run。
- **「老完成率」不是「产量完成率」的子串**：造防误报样本时特意让有效术语是禁用词的**替代词**（产量完成率）——若禁用词是短词（如「完成率」）则替代词必撞，那是业务词表问题不是闸逻辑；合成样本用四字禁用词与五字替代词保持互斥，防止样本自身把"防误报"测成"子串边界"。
