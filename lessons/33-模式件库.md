## 取舍

- **模式件不带公共字段（model_type/version/domain）**：设计裁决说「模式件是素材不是域」，照办——代价是与 archive-registry 的 ontology-model 产物类（要求三字段）冲突，解法是收窄该类 pathPatterns + 新立 ontology-pattern 类，而不是给模式件塞假字段把闸哄绿（那是登记表说谎）。
- **fragment 占位符一律双引号包裹**：实测裸 {{域前缀}} 落 YAML 流解析直接语法错误（引用号形态验过：引号嵌 ID 与列表均安全）——这条写进模式件头注、pattern-usage.md、探针残留检查三处，负变体 ac3-bad-fragment 钉死。
- **探针只对首批五件做「全命中」不做「恰好五件」**：出货集红绿钉清单内容（缺件/改名即红），不钉总数——模式件库按 L0 裁决扩充时不需改出厂集。
- **组合示例只组合两件（state-machine-lifecycle + coded-dictionary）**：票面指定；M3 状态迁移规则是模式件 compose_notes 点名的「组合后按证据决定」补件，示例域无素材证据故不建（manifest omittedModels 理由注明），恰好实证「模式件给形态、业务内容取素材」的纪律。
- **compose-example 的词典项留一条 enabled: false**（DISABLED 停用）：把 validity-versioning 的停用保留行纪律顺带演示在组合产物里，不另建第三件组合。

## 坑

1. **patterns/*.yaml 撞 archive-registry 的 ontology-model 产物类**：pathPatterns `ontology/**/*.yaml` 在 fnmatch 下通配任意层，模式件全数命中三公共字段检查（实跑 3 处 missing-field 违规）。照主窗口预案「照实补登记」处理（取舍 1）；教训=登记表 pathPatterns 用 `**` 时新增受管子目录先想产物类归属。
2. **fixtures 深度不同、schema 符号链接相对深度不同**：expected-output/<域>/ 下的先例是 `../../../ontology/schema`，本票 compose-example 直接挂 fixture 根下只需 `../../`——链深错误不报「链接坏了」而是「没有 schema/ 目录」，排障先看链接指向再怀疑闸。
3. **GLS definition 里写 `enabled: false` 未加引号 = YAML 语法错误**：冒号+空格在裸标量里是映射语法，schema_check 报 mapping values are not allowed here；含冒号的值一律引号包裹（模式件 compose_notes 大段散文用 `>-` 块标量天然免疫）。
4. **探针目录参数曾误写进非契约字段 args**：fixture_run 断言契约只有 type/cmd/outputContains/path/contains/pattern/golden，cmd-fails/succeeds 的参数必须拼在 cmd 字符串里（{fixture_dir} 替换只认 cmd 内占位符）。
