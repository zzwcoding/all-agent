# lessons/63 · 多域防呆四件（票 77）

## 做了什么
三域接入复盘拍板的防呆四件一次落齐：① onboard_check 新域接入 checklist（逐域十项一条命令，硬项 manifest/语义闸/devkit exit 1，软项只警不拦——三域实跑硬面齐，his 审记 pending 与 L5 面未建如实警告）；② 协议枚举化（meta_probe --list-domains 域清单现跑为准 + review_gate verify --all 逐件核，cmd_verify 核心提炼为 verify_record 供三工具共用，AGENTS 批收官清单①⑥去三域硬编码名单、新增⑧指标快照条）；③ report_numbers 指标快照（667 测试/三域/五生成物审记态现跑机取，落 docs/meta/指标快照-2026-09-27.md）；④ 归档闸未跟踪文件警告（只警不拦）；顺带从 git 历史恢复票 76 日志为 lessons/62。

## 坑
1. verify_record 提炼时把配置错从 stderr 改成了 stdout——四条既有测试当场红（票 45 契约：配置错走 stderr）。提炼/重构前先 grep 既有断言对输出流的期望，输出流是契约的一部分；
2. unittest discover 对同名测试模块二次发现会撞车（两个临时夹具都叫 test_dummy，第二个 collect 直接炸）——discover 用的模块名必须逐测试唯一；
3. L5 词面检查初版只扫 fixtures/l5-scoring/expected（出厂占位）+ docs/meta 留痕，bohai 被误报「评分面未建」——金集真身在 fixtures/semantic-service/expected-answers/；更隐蔽的是挂账说明（l5-评分-*-挂账说明.md）里顺带提及他域名，是「缺席的证据」不是「在册的证据」，须按文件名排除；
4. 各测试文件的 run_main 助手返回值不一致（有的二元组有的三元组、有的不接 SystemExit）——复用前先读签名，别按记忆写；
5. 三域审记状态 heterogeneity（bohai 双件 pass / his 双件 pending / pkb 单件 pass+skillpkg 豁免）——工具输出必须逐件如实报，不能假设「全绿」或「全欠」。

## 取舍
- onboard_check 不进 ci.sh：它是第四域接入时点的一次性核对命令，不是常驻闸——常驻化（CI 里强制文档对齐）误报面大，留作后续票再议；
- 未跟踪文件警告只警不拦：开发中途树上有未跟踪文件是常态，硬闸会把 CI 变成 git add 纪律警察；防丢的真正闸口是提交前（协议⑩ 最终树四闸）+ 这条显式警告；
- 软硬分级：机器可判的在场性（manifest/schema/devkit）为硬，依赖人审节奏的（审记 pending）与文档对齐面（AGENTS 行/路由表词面）为软——把人审节奏当硬闸会逼人伪造审记。
