## 批次一 · L5 评分线（票 42–44，串行）

设计案：docs/design-l5-scoring.md。核心裁决：评分器 = 运行时子 agent 注入（脚本零模型调用，只消费评分结果 JSON 文件）。

### 票 42：L5 评分器确定性骨架（脚本轨 TDD）
- 范围：`tools/l5_score.py` CLI——rubric 格式校验（缺锚定例/权重非法/引用参照答案不存在 → 红）/ 评分结果文件校验（严格 JSON、维度齐、分数 0–5 合法，脏数据判"评分无效"）/ 3 采样中位聚合 / 分差 ≥2 标"不稳定" / disqualifier 一票否决 / 通过线判定（单问 ≥3 且中位 ≥4 且无 0 分）/ 报告落盘 `docs/meta/l5-评分-<日期>.md` + 同名 .json / 退出码契约（0 绿 1 红 2 配置错）
- 出厂集 `fixtures/l5-scoring/` 正负变体：rubric 缺锚定例红 / 权重非法红 / 评分 JSON 脏数据红 / 中位聚合正确性断言（mock 评分文件注入）/ disqualifier 触发红 / 正常流转绿
- 随票定：评分提示词载体（设计案开放问题④，倾向随 rubric 进 fixtures）+ 子 agent 评分请求/结果 JSON 协议成文（编排 skill 侧契约，供票 44 接线用）
- 验收：正负变体全过 + 退出码契约断言 + 四闸全绿

### 票 43：Golden 扩编 + rubric 内容（skill 轨出厂集先行）
- 范围：新增 6 问 + 参照答案（接 check_citations 闸）+ 12 份 rubric（含 5/3/1 分档锚定例，锚 5 例引参照答案原文）+ 存量 6 问补 rubric
- **先清单后施工**：新增 6 问的具体问句与取材先落票面清单，L0 过目后再施工（照票 41 先例；设计案开放问题③）
- 验收：每问"机判先绿再进评分"流水断言 + 12 份 rubric 过票 42 格式校验 + L0 过目记录 + 四闸全绿

### 票 44：节奏接线与文档对齐（小票）

## 批次二 · 人审闸线（票 45–47，串行）

设计案：docs/design-human-review-gate.md。核心裁决：审记旁档状态机 + 哈希锚定；manifest 免审 / skillpkg 首审+变更审 / devkit 全审。

### 票 45：审记格式与状态机脚本（脚本轨 TDD）
- 范围：`tools/review_gate.py` 四动作（init/approve/reject/verify）+ verify 现算 sha256 与审记锚定比对（不一致即报失效回落待人审）+ 退出码契约（0 一致 / 1 失效或缺失 / 2 配置错，照 --check 家族惯例）+ specs/archive-registry.json 登记 review-record 产物类（照票 37 先例，requiredFields 实跑驱动收敛）
- 出厂集 `fixtures/review-gate/` 正负变体：审记缺字段红 / 哈希不匹配红 / verdict 非法值红 / 正常流转绿 / 失效后重审恢复绿
- 随票定：reviewedBy 形式（开放问题③）
- **验收核心 AC**：verify 对"生成物被再生"场景必须红（负变体钉死自动失效语义）+ 四闸全绿

### 票 46：三生成物接线与档位登记
- 范围：三生成物落档位（manifest 免审 / skillpkg 首审+变更审 / devkit 全审）+ devkit/skillpack 生成器头部 status 行追加审记指针声明（**生成器字面变更 → 同票重 gen + --check 同步刷新**，本设计唯一合法触碰 exports 的路径，照票 35/36 先例）+ 批收官清单/回归底线增 verify 命令（软闸措辞：审记缺失或失效 = 挂账项，不阻塞四闸）
- 随票定："只审 X 节"声明粒度（开放问题④）+ 新产物判档时机入登记表维护纪律（开放问题⑤，推荐：产物随票诞生即定档）
- 验收：三生成物 verify 实跑状态正确 + exports 重 gen 后 --check 全绿 + 四闸全绿
