# All-agent PRD

状态: 已定稿（2026-09-17 逼问收敛，四项 B 类决策已确认）
信源: RESOURCES.md（R 编号）

## 一句话

**All-agent = 企业语义中台 + 建造/运行一体化平台**：本体仓（Git+YAML）为唯一真源，多输入（需求/数据库/源代码/文档）多输出（应用包/Skill/MCP/分析报告/运行时语义服务），三循环自迭代。形态：skill+脚本，不建代码系统（已拍板）。

## 架构定型（已过讨论，细节见 docs/design-sdd-flow2.md 与 diagrams/all-agent.html）

编译器架构：N 前端适配器 → 语义 CI 闸 → 本体仓（IR）→ M 后端生成器；运行时服务面只读（图索引是派生物，Git 是真源）；三循环（业务语义/建造/元循环）；Harness 用现成 Kimi Code 不自建。

## 技术栈（选型已定，信源 R3）

| 技术 | 用途 | 约束 |
|---|---|---|
| Python 3 stdlib | 闸与工具脚本主体 | 默认零依赖 |
| PyYAML（safe_load） | 本体 YAML 解析 | 唯一被迫引入的第三方，零传递依赖；脚本只读不写 YAML |
| 纯 Python 内存图（dict 邻接表+自写 BFS） | 图谱索引 | 启动时从 YAML 重建；索引是派生物可随时丢弃 |
| mcp（官方 Python SDK） | MCP 发布器 | 仅发布侧安装；stdio 默认，HTTP 改一行 |
| Git | 本体仓权威源 | MR 审批制；派生物禁手改 |

## 功能清单

### 核心（真源与闸）

**F1 本体仓 Schema**
- 做什么：定义本体 YAML 的 schema——以 OMF v9 七模型（M1 对象/M2 行为/M3 规则/M5 主体/M6 流程/M7 报表/MU UI）为蓝本裁剪起步（2026-09-19 票 10：+GLS 术语模型，注册表现八模型类型），一模型一文件、ID 前缀+xxxRef 引用约定、四层规则下沉判定（R1 §16.1–4）
- **模型注册表**（schema 的目录页，机读）：每个模型类型声明 camp（business-core/integration/build-contract）、consumers（runtime/build）、profiles（可用组合）、dependsOn（类型层依赖白名单）——profile 裁剪、检索面划界、生成器在场校验三件事共用此表（2026-09-17 讨论定型）
- **运行期四外衣字段预留**（一期只定义不消费）：M2 行为带契约/风险级/幂等可选字段；M3 规则分"叙述式/表达式"两写法；模型带版本与有效期——为业务 agent 运行期消费预留"可被消费性"，防 schema 二次断裂（R7、R1 §16.10）
- 不做什么：一期不建 ME 事件/M4 场景/MM 映射/MI 接口（v9 裁剪逻辑：先同步世界，异步需求实证后回加，R1 §16.6）；不做 OWL 导出；不做模式件库（二期：可复用建模片段仓，组合产物只是草案、须人审进仓）
- 要点：字段换义宁可新增字段不复用旧名（R1 §16.10）；字典项停用不删除（R1 §16.9）

**F2 语义 CI（五级闸）**
- 做什么：L1 schema 合法 → L2 引用与双向一致（8 组一致对是现成 lint 清单，R1 §16.2。2026-09-19 勘误：一致对清单实为 6 对——权威出处 digest §12.2，第 7/8 组出处未找到，对账见 ontology/schema/schema.md §14）→ L3 指标/SQL/安全 → L4 权限/兼容 → L5 行为回归（Golden 集）
- 不做什么：L5 一期只做结构断言级（出厂集同款 runner），不做 LLM 评分（2026-09-20 勘误，票 44：结构断言级已建（票 42–44，core 机判十二问 + 出厂集断言）；LLM 评分级骨架与评分集已落（l5_score.py + 12 问 rubric），按 design-l5-scoring 节奏触发——批收官软闸 / 发布前硬闸，不进 ci.sh 每提交）
- 信源：R4（DataBuddy 五级语义 CI）、R1 §校验门禁

**F3 图索引构建器**
- 做什么：本体 YAML → 内存图（多跳遍历、ID 引用闭包、影响链计算）
- 不做什么：不持久化、不接图数据库（R3 结论：纯 Python 内存图，启动重建）

**F4 运行时语义服务（只读）**
- 做什么：受控检索瀑布（显式锚定优先、逐级升级、可拒答）+ 口径解析 + 子图装配（对象连同行为/规则/权限打包成 Agent 上下文）
- 不做什么：一期不写路径（Agent 改语义只许走 F13 的 MR）
- 信源：R4（S0–S8）、R2

### 前端适配器（多输入，各产出本体草案、必经 F2 进仓）

**F5 需求探索器**：原始需求 → 反问收敛 → 本体草案（"AI 只做格式转换，业务必须人确认"）
**F6 数据库逆向器**：DDL/库表 → 本体草案（自下而上证据，业务 Owner 裁决）
**F7 代码逆向器**：存量源码 → 本体草案 + 调用链素材
**F8 文档萃取器**：文档资料库 → 概念/术语/规则草案

### 后端生成器（多输出，只读仓）

**F9 应用生成器**：本体 + 技术架构约束 + 开发指导书 → 导出开发包（交接给编码 agent 的轻形态，不做平台内 IDE）
**F10 Skill 发布器**：本体切片 → 可对话技能包
**F11 MCP 发布器**：本体能力 → MCP Server（官方 SDK，stdio 先行）（2026-09-19 注记：票 23/24 已建——stdio 服务器 `tools/semantic_mcp_server.py` + capability manifest 生成器 + 端到端实弹走查，消费文档 `docs/mcp-server.md`）
**F12 变更影响分析器**：本体变更 → 影响链路 + 建议落地顺序（逆向产物的最高价值，R1）

### 循环

**F13 提案池与 MR 流程（业务语义循环）**：三源信号（监督/自检/交互）→ 提案池 → 冲突检测 → MR 人审 → 语义 CI 回归 → 合入（2026-09-19 票 18/19 已建：proposal-pool skill+确定性冲突预检+提案池实弹 31 份）。四条红线：不直改主干/只提 MR/不手改派生物/高影响必人工审批（R4）
**F14 元循环体检**：跨层探针（建造层打回率/运行层拒答率与 Golden 准确率/资产层覆盖率与孤儿数）+ 出厂集回归 + 信号路由表（业务错→MR / 工程错→sdd-flow2 票 / 元模型错→schema 版本演进+迁移票）+ 定期体检节奏

## 首个业务域（建议，待拍板）

**渤海油田产量域**——复用 R5（teach-petro-agent 设定书 v3：8 表 DDL、指标口径库、治理角色链、术语）作为第一个接入域的素材，省掉冷启动；同时它是"已经被讲过一遍"的域，便于校验本体建模的保真度。

## 明确不做什么

- 不建代码系统/平台 UI（skill+脚本路线已拍板）
- 不自建 Harness（用 Kimi Code 现成底座）
- 一期不做写侧自动执行：Agent 对业务系统只到"提案"，行动侧是后续版本
- 一期不做向量检索（检索瀑布走 ID 锚定+图遍历+BM25 级文本匹配）
- 不做 OWL/SHACL/SWRL 导出（经典本体论是子集，需要时再补导出器）

## 决策记录（2026-09-17 逼问收敛，全部已确认）

1. **一期用户范围**：单人使用（仓主自己）；多人协作与业务 Owner 在线审批留二期。MR 人审由仓主在 Git 完成。
2. **生成器产出人审闸**：设——开发包/MCP 发布前过一道人确认；二期可按生成器置信度放开。
3. **一期范围**：F1–F4 + F6 + F12（仓→闸→索引→只读服务→DB 逆向→影响分析）；其余二期。首个接入域 = 渤海油田产量域（试验原料：R5 设定书的 8 表 DDL/指标/术语；选它的理由=业务真相已知、可对照验收）。
4. **量级与合规**：单域数百对象级、单机单用户、无并发/国产化/密评等合规硬要求（一期为方法论验证，非生产交付；合规要求进来则回炉选型）。
