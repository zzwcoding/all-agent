# All-agent PRD（粗稿）

状态: 粗稿
来源: 2026-09-17 方向讨论（本体建模框架 × sdd-flow/teach-flow 对账）落盘

## 一句话

建一个**企业语义中台 + 建造/运行一体化平台**：本体仓为唯一真源（IR），多输入（需求/数据库/源代码/文档）多输出（应用/Skill/MCP/分析报告/运行时语义服务），三个循环嵌套自迭代。

## 架构定型（已讨论确认）

- **编译器架构**：N 个前端（适配器：需求探索/DB 逆向/代码逆向/文档萃取）→ 本体 IR（Git+YAML）→ M 个后端（应用生成/Skill 发布/MCP/变更影响分析/运行时语义服务）。
- **铁律**：所有方向只跟本体仓说话，方向之间不许直接连线；加一个输入/输出 = 加一个插件。
- **Git 是唯一真源**，图谱索引、运行时缓存、导出包全是可重建的派生物，禁手改。
- **稳定 ID 体系**是跨方向黏合剂（对象/行为/规则/指标，引用只走 ID）。
- **语义 CI**（五级：语法→引用一致→指标SQL安全→权限兼容→行为回归）是所有输入的公共闸门。
- **运行时服务面只读**；Agent 对语义的修改走 MR（自动化止于提案）。

## 三个循环

1. **业务语义循环**（已有设计）：本体 → Agent 消费 → 三源信号 → 提案池 → MR → 语义CI。
2. **建造循环**：sdd-flow（本平台自身也用 sdd-flow 建造——自举，造完用代码逆向器把自己逆向进仓当狗粮）。
3. **元循环**（新增，本项目的关键增量）：跨层探针（建造层：一次通过率/打回率；运行层：Golden Q 准确率/拒答率；资产层：覆盖率/孤儿对象）+ 出厂集回归 + 信号路由表（业务错→MR / 工程错→sdd-flow 票 / 元模型错→框架版本演进+迁移票）+ 定期架构体检。

## 与其他方法论的关系（决策已记录）

- sdd-flow 是建造拍：本体覆盖不了的工程层（NFR/并发/边界/CI）由它接管。
- 本体框架（sharptoolbox/ontology_modeling_framework，v6 十一模型/v9 七模型）是领域知识来源与 Schema 参考。
- 落地次序：① 本体仓+Schema 校验 → ② 图索引+只读语义服务 → ③ DB 逆向器 → ④ 变更影响分析器 → ⑤ 应用生成器（最后，先用"导出开发包+编码 agent"轻形态）。
