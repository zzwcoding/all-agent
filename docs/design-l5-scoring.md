## 0. 一句话结论

L5 采用 **"离线批评分器"形态（选型 A）**：Golden 集从 6 问扩编到约 12 问并逐问配 rubric，评分器对"机判已绿的回答"按 0–5 档打分，通过线 = 单问 ≥3 且中位 ≥4 且无 0/1 分；**不进 ci.sh 每提交**，只在批收官或发布前手动触发，留痕落 `docs/meta/`，红灯走既有信号路由表分道打回，不覆盖机判结论。

## 1. 问题定义：什么必须 LLM 评分，什么不该

### 1.1 现状：L5 停在结构断言级

- CONTEXT.md「语义 CI」词条定义五级：L1 语法合法 / L2 引用与本体一致 / L3 指标·SQL·安全 / L4 权限·兼容 / **L5 行为与检索回归（Golden Question + 出厂集）**。
- PRD F2「不做什么」明示："L5 一期只做结构断言级（出厂集同款 runner），不做 LLM 评分"——本设计案即补这一欠账（一期收官报告 §6 #1、二期收官报告 §6 #1 两次在册）。
- 现行 Golden 面（注源为实）：
  - `fixtures/semantic-service/questions/golden-questions.md`：**6 问**（Q1–Q4 票 04 + Q7/Q8 票 17），各配参照答案（`fixtures/semantic-service/expected-answers/` 6 份）；
  - `tools/semantic_service_core.py`：**core 机判八问 CORE-01–08**（票 22），对真域逐问钉 status 与命中 ID——二期收官报告 §3 所称"八问回归"即此。
- 机判面已管住的结构断言（L5 不重复判）：命中/拒答 status 钉死（assertions.json）、答案 ID 引用清单正文↔清单一致（`tools/check_citations.py`，票 13 CIT-01–05）、禁用词话术守卫正则（`fixtures/semantic-service/guard-corpus/` + `tools/guard_corpus_check.py`，票 16/20）、行为 ID 集（`--impact` 机读佐证）。

### 1.2 必须交给 LLM 评分的三类"说得对不对"

机判面判的是"答案的骨架对不对"（命中 ID、状态、禁词词面），管不到"血肉对不对"。三类必须 LLM 评：

1. **参照答案的语义保真度**：回答与参照答案在语义上是否一致——要点齐不齐、有没有答非所问、有没有用词造成的误导（词面正则拦不住"把替代口径说成主要口径"这类语义级偏差）。
2. **口径解释质量**：命中正确 ID 之后，解释是否组织成可消费的叙述（定义/规则/出口分层清楚、近邻指路说得通），而非 ID 堆砌。
3. **拒答话术恰当性**：拒答分支（缺件/面外/禁用词三分支，specs/semantic-service.md AC3/AC4 + 票 17 AC2/AC3）的"说明缺什么、指路指得对不对、语气是否越权补猜"——守卫正则只管禁词形态，不管话术是否恰当。

### 1.4 机判管不到的典型形态（举偶，全部为语义级、词面级机判不可达）

- **误导性强调**：回答把替代口径摆在主位、把主口径一笔带过——词面上无任何禁词、引用 ID 全真实（`check_citations` 绿、守卫正则绿），但语义上已经答歪。这只能由"对照参照答案评语义保真度"抓住。
- **要点漏述**：装配集齐、ID 引用齐，但漏说承载规则的适用条件——机判断言"该在场的都在场"，断言不了"该说的都说了"。
- **越权补猜**：拒答话术里夹带"大概是因为…"式推测——不编造 ID（机判白名单断言绿）、不出现禁词，但违反"未找到不猜"的行为约定（specs/semantic-service.md 行为约定），属话术恰当性问题。

这三类的共同点：**每一条单独看都不违反任何一条机判断言，合起来就是"说得不对"**——L5 的存在理由。

### 1.3 不该交给 LLM 评分的（红线）

- **结构性正确**：status/命中 ID/引用清单/禁词形态——机判面已全绿才进 L5，L5 不重复判（重复判只会引入不稳定的第二答案源，稀释机判权威）。
- **确定性可判子集**：票 41 已把 L3 中可机判部分（sourceField 存在性/表达式引用/SQL 只读/规则形态）落成 `l3-*` 违规码——凡是"能写成断言的"永远不进 L5。
- 判分依据写成可枚举清单的项（如"答案必须含引用清单节"）——那是 `check_citations.py` 的活。

**分层原则一句话**：机判管"对不对"，L5 管"好不好"；机判绿是 L5 的入场券，不是 L5 的评判对象。

## 2. 评分器形态三选型对比

| 维度 | A. 离线批评分（发布/收官前，强模型评 Golden 集） | B. 运行时自评（模型给自己答案打分） | C. 双模型交叉评 |
|---|---|---|---|
| 成本 | 低且可控：只在批收官/发布前触发，Golden 集 ~12 问 × 3 采样，单次 ~60–80k token（§5 估算） | 名义最低（同一次调用），实际把评分延迟与 token 摊进每一次问答 | 高：评分量 ×2 起步，分歧仲裁还要第三者 |
| 稳定性 | 高：离线批处理、温度 0、可 3 采样取中位、失败可重跑不阻塞anything | 低：评分混进运行时路径，延迟波动直接伤服务；采样预算受在线约束 | 中：两模型系统性偏差不同，分歧率本身成为新噪声源 |
| 自评偏置 | 无：评者 ≠ 答者（评分用强模型评 skill 的成稿） | **实锤风险**：LLM 对自产文本系统性偏高，而语义服务的核心承诺恰是"不编造、可拒答"（specs/semantic-service.md 行为约定）——最需要独立评判的地方偏偏用了利益相关方 | 低：两个独立评者互证 |
| 与现行架构的契合 | 高：本仓已接受"批级独立审查后置"节奏（ADR 0002：外部审查窗替代票级 review，权衡明确接受问题发现后移）——L5 评分就是同一哲学的机器版 | 冲突：票 22 提纯裁决"机判归 core、成稿归 skill"，运行时再加自评闸打破刚收敛的分工 | 中：引入第二个模型供应方=新依赖（本仓工具链现为纯 Python 零外部服务，ci.sh 四闸全本地） |
| 失败模式 | 评分窗没跑 = 空窗（靠批收官清单纪律兜住，AGENTS.md 续跑协议第 9 条已有同类四件） | 服务被评分拖慢；偏置让坏答案常态化过闸 | 交叉分歧无仲裁者时退化为人工，等于没自动化 |

### 推荐：A 为主，按需升级到 C 的子集形态，B 明确不做

- **A 为主**的理由：成本与节奏匹配（批收官/发布前才有"发布"语义可评）；与 ADR 0002 确立的批级后置审查哲学同构，不新增流程范式；评者≠答者保住独立性。
- **C 的子集形态按需启用**：仅当某问评分落在通过线附近（如中位恰为 3.5）或两次触发结论翻转时，才对该问升级第二模型仲裁——把 C 的成本从"每问恒付"改为"争议才付"。
- **B 不做**的理由是结构性的而非成本的：自评在利益结构上无效（偏置方向恒为利好自己），且票 22 刚把运行时收敛为"确定性 core + skill 成稿"两层，再塞一层自评闸是架构倒退。

## 3. Golden 集扩编方案（6 问 → ~12 问，每问带 rubric）

### 3.1 扩编原则

- 现存 6 问（`fixtures/semantic-service/questions/golden-questions.md`）**不换问题、只补 rubric**——它们的参照答案（expected-answers/ 6 份）已按 skill 工序手工产出并接了 `check_citations` 闸（票 13/17），是现成的 5 分锚定例。
- 新增问一律"考话术质量，不考机判已管的骨架"：每问的 status/命中 ID 仍由 core 八问同款机制先机判，机判绿才进评分。
- 参照答案继续"手工按工序产出 + 带引用 ID 清单"（现有纪律，票 04 起不变），新增答案同样接 `check_citations` 闸。

### 3.2 扩编维度与配额（域无关，各域按此四维复制）

| 维度 | 现状 | 新增 | 每问评分要点（rubric 骨架，落盘时逐问细化） |
|---|---|---|---|
| 口径正答 | Q1/Q7 存量补 rubric | +2：①多义候选问（考"列候选请锚定、不擅自合并"话术）；②闭包叙述完整度问（考装配集分层叙述，非 ID 堆砌） | 要点覆盖齐 / 分层组织可消费 / 引用 ID 全部真实且必要（机判已管真实，此处评"必要"） |
| 拒答话术 | Q3 存量补 rubric | +2：①缺件分层说明问（考"缺什么/谁该补/近邻是什么"三段话术）；②近邻指路恰当性问（指路 ID 正确由机判管，此处评"指路解释是否让提问者能走通下一步"） | 不越权补猜 / 缺件说明分层 / 指路可行动 |
| 禁用词处置 | Q8 存量补 rubric | +1：替代口径引导话术问（禁用说明→替代口径→真实 ID 指路的三步叙述是否连贯；禁词不答成可用由守卫正则机判，此处评引导质量） | 三步齐 / 替代口径解释到位 / 不留"还是能用"暗示 |
| 面外拒答 | Q4 存量补 rubric | +1：面外说明话术问（考"为何面外+该走哪条流程"的说明质量，不泄露面外细节由守卫机判） | 面外理由说清 / 零细节泄漏（复述机判）/ 流程指路明确 |

合计：存量 6 问补 rubric + 新增 6 问 = **12 问评分集**。新增问的解析证据可复用 core 八问同款真域取材方式（票 17 先例：GLS 取真域、问答本体不扩文件），具体问题在施工票里定稿并过 L0。

### 3.3 rubric 落盘格式（确定性骨架，可机判）

每问一个 rubric 块，随参照答案同目录落 `fixtures/semantic-service/rubrics/`：

```
question: Q9（多义候选话术）
reference: ../expected-answers/ac9-ambiguity.md
dimensions:
  - id: coverage      # 要点覆盖
    weight: 2
    anchors: {5: "...", 3: "...", 1: "..."}   # 分档锚定例，锚 5 例引参照答案原文
  - id: organization  # 分层组织
    weight: 2
  - id: citation-fit  # 引用必要性与组织
    weight: 1
disqualifiers:       # 一票否决项（与机判面零重复：只列语义级）
  - "编造装配集之外的承诺性表述"
```

rubric 的**格式与权重合法性是机判的**（进出厂集：缺锚定例/权重非法/引用参照答案不存在 → 红），**打分是 LLM 的**——LLM 只拿到"问题+参照答案+被评答案+rubric"，输出逐维分数与理由。

## 4. 门槛与误报处置

### 4.1 分档（0–5，逐问逐维打分后聚合）

- **5** 忠实参照且话术完整，可直接作范例；**4** 忠实参照、话术有小瑕疵不影响消费；**3** 要点齐但表述含糊/冗余；**2** 漏一个要点或有误导性表述；**1** 语义偏离参照（答非所问/要点错位）；**0** 触发 disqualifier（编造承诺、越权补猜、语义级把禁用口径说成可用）。

### 4.2 通过线

- **每问总分 ≥3**，且**全集中位 ≥4.0**，且**无任何问触发 disqualifier（0 分）**。三条同时满足才叫 L5 绿。
- 理由：单问 ≥3 挡"个别问崩坏被平均分掩盖"；中位 ≥4 挡"整体平庸"；disqualifier 一票否决保住"不编造"底线语义——这条与机判守卫正则的差别在语义级（正则拦词面，L5 拦语义承诺）。

### 4.3 评分不稳定（同答不同分）的缓解

1. **温度 0 + 固定评分提示词版本**（提示词随 rubric 一起进 fixtures，改提示词 = 改出厂集，走票）。
2. **每问 3 采样取中位**——中位对单次离群免疫；3 采样分差 ≥2 时标记"不稳定"，自动升级第二模型仲裁（§2 推荐的 C 子集形态）。
3. **rubric 锚定例**：每个维度给 5/3/1 分档的锚例，锚例直接引现存参照答案原文——评分器是"对锚打分"而非"凭感觉打分"。这是对"同答不同分"最有效的一招，也是 rubric 格式里把 anchors 设为必填的原因。

### 4.4 低于线的处置（红灯只路由，不自动改）

- 评分器**只报告不修复**：红灯结论落留痕文件，然后按 `policies/signal-routing.json` 既有三类分道——语义内容错（保真度/口径类红）→ **业务错道**（提案池起草，Owner 裁决走 MR）；话术/工序错（拒答话术/组织类红，本体没错）→ **工程错道**（tickets/ 开票修 skill 工序或参照答案）。rubric 本身写错（锚例与工序矛盾）→ **元模型错道**同款处理（改 rubric 走票）。
- 与"误报"的界线：**机判面零误报优先级高于 L5**——若 L5 红与机判绿冲突且复评仍红，处置是"开提案/票让人裁"，绝不是回头怀疑机判；L5 从不推翻机判结论（§6）。

### 4.5 误报（好答案被打低分）的处置链

1. **先复评**：同问 3 采样重跑（评分不稳定是低分的第一嫌疑，§4.3 中位机制本来就为此设计）——中位回升 ≥ 通过线则记"采样波动"，无需开单。
2. **复评仍红 → 查锚例**：低分理由与 rubric 锚定例对照——若被评答案与 5 分锚例实质等价，说明锚例覆盖不足或评分提示词偏差 → **元模型错道开票修 rubric**（锚例修订 = 改出厂集，走票不改脚本）。
3. **锚例无恙 → 才承认是真红灯**：按 §4.4 分道。这条链的顺序是刻意的：**先怀疑评分器、再怀疑 rubric、最后才怀疑答案**——与机判面"红灯先怀疑闸再怀疑数据"的调试次序相反，原因是 L5 的假阳性率天然高于机判面，处置链必须把最不可靠的环节排在最先排查。

## 5. 成本闸

### 5.1 token 预算估算（量级估算，施工票实测修正）

单问单采样输入：rubric ~400 tok + 参照答案 ~500 tok + 被评答案 ~500 tok + 评分提示词 ~200 tok ≈ **1.6k tok**；输出（逐维分+理由）~300 tok。
- **全量跑**：12 问 × 3 采样 × 1.9k ≈ **~70k tok/次**；发生第二模型仲裁时上浮 ~30%。
- **抽检跑**（只评新增/被改问，日常用）：3–6 问 × 3 采样 ≈ **15–35k tok/次**。

### 5.2 触发节奏（结论：不进 CI）

- **不进 ci.sh 每提交**：四闸的价值在秒级反馈，70k token 的评分放进每提交等于把 CI 变成慢闸+烧钱闸，且评分不稳定会制造假红灯打断串行流水线（续跑协议第 2 条"一派一验一提交"会被评分噪声阻塞）。
- **触发点两个**：① **批收官**（挂进 AGENTS.md 续跑协议第 9 条批收官清单，作为第 ⑤ 件——但**软闸**：红灯开工单，不阻塞收官留痕）；② **发布前手动触发**（语义服务对外发布/新域接入验收时，此时为**硬闸**：L5 红则不发）。
- 节奏量级：批收官频度（本仓史实约月频）× ~70k tok——成本可忽略，纪律价值在"发布语义出现时评分必然在场"。

| 触发点 | 强度 | 跑法 | 红灯后果 |
|---|---|---|---|
| 批收官（协议第 9 条第 ⑤ 件） | 软闸 | 全量跑，留痕必落 | 开提案/票（信号路由分道），不阻塞收官留痕与锚点推进 |
| 发布前 / 新域验收 | 硬闸 | 全量跑 + 留痕随交付物引用 | L5 红则不发布；复评仍红走仲裁升级（§2 C 子集形态） |
| 日常开发 | 不触发 | —（机判四闸够用） | — |

### 5.3 留痕

- 评分报告落 `docs/meta/l5-评分-<日期>.md` + 同名 `.json` 机读伴生（照 `docs/meta/体检-*.md` 既有形态：同名已存在加序号后缀追加、不覆盖旧留痕，AGENTS.md 续跑协议第 9 条同款纪律）。
- 留痕内容：每问逐维分数+采样分布+仲裁记录+结论+路由去向（红灯必填）——红灯可追溯到"哪一问哪一个维度几票红"。

## 6. 与机判面的关系

1. **L5 红不覆盖机判绿（分层声明）**：机判面（ci.sh 四闸）是硬闸，结论唯一；L5 是发布/收官节奏上的软闸+发布前硬闸。两者冲突时信机判、人裁 L5——理由：机判可复现（同输入同输出），LLM 评分三采样仍可能翻转；让可复现层永远拥有一票，不可复现层只有建议权。
2. **L5 的输入前提是机判绿**：评分器只接受"core 八问同款机判已通过的回答"进入评分；机判红的回答没有评分资格（红灯在机判层就地处理，不用 LLM 复核一遍浪费钱）。
3. **评分面与机判面零重复**（§1.3 红线）：rubric 里凡涉及"ID 在场/禁词形态/清单一致"的维度一律不设——那些已由 `check_citations.py`、`guard_corpus_check.py`、assertions.json 机判；rubric 只设语义/话术/组织维度。
4. **独立留痕，不混入体检**：L5 留痕独立于 `meta_probe` 体检文件（体检是纯机判硬闸，L5 混入会让"硬闸全绿"语义被软闸污染）；meta_probe 不加 L5 探针项，L5 也不反向要求体检给它背书。

## 7. 明确不做与开放问题

### 明确不做（本设计案边界外）

1. 不做运行时自评闸（选型 B，§2 已裁）。
2. 不做 L5 每提交触发、不进 ci.sh 四闸（§5.2 已裁）。
3. 不做"评分器自动改写答案/参照答案"——红灯只路由给人（§4.4）。
4. 不做 L3 的 LLM 语义级（指标合理性/SQL 语义正确性）——那是 L3 后续票的账，本案只管 L5；两者共用本框架的评分器骨架是可能的，但不在本案承诺。
5. 不做多域并发评分——先单域打样走通，第二域接入时复用（域无关性由 §3.2 四维骨架保证：换域 = 换参照答案与 rubric 内容，评分器与门槛不动；不用现在实现多域）。
6. 不承诺评分器模型选型（用哪个具体模型/本地还是 API）——开放问题 ①，施工票前 Owner 拍板。

### 开放问题

1. **评分器用什么模型**：（**已裁决，见 §9**：运行时子 agent 注入，"外部 API vs 本地模型"二选一取消）。
2. **Owner 是否抽检校准**：L5 绿的批次 Owner 要不要按比例人工复核评分结论，防评分器系统性漂移（可复用 ADR 0002 的"L0 复核证伪则推翻"推翻条件句式）。
3. **新增 6 问的具体问题定稿**：本方案只定维度与配额，具体问句与参照答案在施工票产出后过 L0（照票 41"子集清单 L0 裁决入票面"先例）。
4. **评分提示词的版本化载体**：随 rubric 进 fixtures（本方案倾向）还是独立 prompts/ 目录——施工票 1 定。

## 9. Owner 裁决记录（2026-09-20）

- **裁决①（开放问题①·评分器模型）**：不选"外部强 API"也不选"本地模型"，采用第三形态——**运行时子 agent 注入**。评分器不内嵌任何模型调用：编排 skill 逐问派发**全新子 agent**（零上下文，评者≠答者结构性成立；模型 = 运行时所装，可经派发参数指定强模型），子 agent 输出严格 JSON 评分结果落盘；`l5_score.py` 只消费评分结果文件（格式校验 → 中位聚合 → disqualifier 一票否决 → 报告落盘 → 退出码），全程不碰模型，仓保持"纯 Python 零外部服务"现状。数据出境面不新增（评分流量与日常会话同路），模型选型随运行时配置走，不落成仓内依赖。
  - 施工含义：§8 票 A 的"评分函数注入点"接口定为**评分结果文件注入**（mock = 预置 JSON 文件）；子 agent 输出的严格 JSON 格式校验与"评分无效重派"纪律在票 A 钉死；3 采样 = 3 次独立子 agent 派发（§4.3 机制不变，载体从"温度 0 重跑"改为"独立派发"，分差 ≥2 触发仲裁升级不变）。
- **裁决②（其余全部）**：按设计案推荐执行——离线批评分形态（§2 选型 A，B 不做、C 降级为争议仲裁子集）、Golden 6→12 扩编（§3）、通过线与误报处置链（§4）、不进 CI 的节奏（§5.2：批收官软闸 / 发布前硬闸）。
- **随票定不再单裁**：开放问题 ②（Owner 抽检校准，随票 C 定）③（新增 6 问定稿，随票 B 过 L0）④（评分提示词载体，随票 A 定）。
