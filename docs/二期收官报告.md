```
python3 tools/app_pack_gen.py ontology/bohai --check exports/devkit/bohai/devkit.md
python3 tools/skill_pack_gen.py ontology/bohai --models M1,M2,M3,M7,GLS --check exports/skillpkg/bohai/SKILL.md

python3 tools/review_gate.py verify exports/devkit/bohai/devkit.md    # 审记 verify 软闸（票 46 起）：审记缺失或失效=收官挂账项，不阻塞四闸
python3 tools/review_gate.py verify exports/skillpkg/bohai/SKILL.md   # 同上（软闸）
```

footgun 注记：manifest `--check` 的 target 必须传 `ontology`（仓根）——传 `ontology/bohai` 会因 manifest 生成范围不同而误报不一致（票 37 实证：仓根 exit 0 / bohai exit 1）。

全绿 = 七条底线（前四条为 CI/体检硬闸，后三条防生成物陈旧）+ 审记 verify 两条软闸（票 46 起：审记缺失或失效=收官挂账项，不阻塞四闸；manifest 免审级不要求审记）。新 clone 记得 `git config core.hooksPath tools/hooks`。

## 5. 二期方法论收获（新增，按分量排序）

1. **覆盖不变量探针**：「输入标记的每个条目必须落到草案/问题/疑点之一」机判化——三个适配器共用同一模式，负变体删一词/一符号/一行即红（审查实证"全部真红"）。
2. **实例指针机判**：路由表 commit 逐个 git log 验存、PROP 全量查池——把"审查经验"反哺成闸的标准动作。
3. **--check 防陈旧**：生成物入库可再生逐字节比对（manifest/devkit/skillpack 三处）——派生物禁手改的机械面。
4. **人审头+可再生**：PRD 决策 2 的生成物落位——status 头声明+确定性再生，人审的是内容不是格式。
5. **camp/检索面纪律贯穿三处**：core 候选过滤、负变体断言、生成器切片声明——一处判定链（Surface.in_surface）三处消费。
6. **静默失配两次事故**（收官报告 sed、票 24 锚点 replace）→ 协议⑥"替换必须带断言验证"成文——事故变制度。
7. **机判边界自觉**：CORE 断言集相等与答案 ID 集的已知差异、闭环回填以裁决落点 modify 形态登记——差异如实记账不硬凑。

## 6.5 观察项（明示去向）

> 第六轮审查注记级发现（票 37 入账），不构成当前红灯，逐条带去向不悬着。

1. **skillpack 工序路由静态文本无常量级机核**：SKILL.md 内工序路由为静态文本，瀑布演进可陈旧——运行时真源指针（core 单一来源）已缓解。**去向**：随第三期 core 演进票顺手常数化。
2. **app_pack_gen 对 behaviorRef 缺失行 KeyError 裸崩 exit 1**：异常输入下非干净退出，应收敛为结构化 exit 2。**去向**：随下批工具票顺手修（不在本票，本票只入账）。
3. **人审闸翻转承载机制**：现为人审头状态标记，非审批流——PRD 决策 2「按置信度放开」前的待决事项（状态标记→审批流的承载形态）。**去向**：第三期规划输入，随期裁决。
