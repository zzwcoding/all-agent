  - **术语候选**：知识库、RAG、Wiki、知识图谱、GraphRAG、本体（口径取 all-agent-ex TERMS.md 定稿词条，R11——"知识库=仓库；Wiki=人读页面层；知识图谱=实体关系网；RAG=消费技术；本体=ought/means 登记"）。

## 开放问题清单

每问固定三字段（问题 / 为什么问 / 影响哪个候选元素），三字段齐且问数一致是机判口径；问题质量人审，机判不背书。

### Q1 产品形态与宿主：第二业务域，还是第五期端到端真系统？

- 问题：个人版 WeKnora 以哪种形态落地——(a) All-agent 本体仓的第二业务域（bohai 同款，skill+脚本形态，语义服务/MCP 消费）；(b) 第五期端到端实弹（本体→聚合卡→devkit→sdd-flow 建真系统，独立项目仓）；(c) 在既有 weknora复刻 仓上继续产品化？
- 为什么问：Owner 原话"使用 all-agent 生产一个端到端项目"与 AGENTS.md 第五期候选（本体→聚合卡→devkit→sdd-flow 建真系统，待拍板）吻合，但 (a)(b)(c) 的载体、验收面、四闸适用性完全不同——宿主未定，草案域目录无处落。
- 影响哪个候选元素：全部候选元素的载体；本体草案域目录位置（ontology/<域>/ vs 独立仓）；验收口径（语义 CI 四闸 vs 项目自有 CI）。

### Q2 对象粒度：六类内容是一个对象加类型枚举，还是各自立对象？近义词判别边界是什么？

- 问题：开发资料/想法/文档/书籍/技术感悟/工作业务——建模为单一"知识条目"对象+来源类型枚举，还是文档/书籍/想法等各自立对象？"想法 vs 技术感悟"、"开发资料 vs 文档"的判别边界是什么？
- 为什么问：Owner 原词六类存在近义重叠且无判别边界（判别类含糊）；粒度选择直接决定 M1 对象模型骨架，建错返工面最大。
- 影响哪个候选元素：知识条目 AGG 候选（一对象+类型 vs 多对象拆分）；来源类型属性候选的枚举结构；M1 对象模型整体形状。

### Q3 来源类型的值集全集是什么？

- 问题："开发资料、想法、文档、书籍、技术感悟、工作业务等等"——"等等"之外还有哪些来源类型（如：网页剪藏、视频笔记、课程、对话记录）？
- 为什么问：值集类含糊——Owner 原词以"等等"收尾，枚举只给部分值；按纪律不建枚举（String 占位），全集收敛后才可立值域。
- 影响哪个候选元素：知识条目 AGG 候选.来源类型（枚举值集候选）。

### Q4 检索栈与量级口径：向量库/embedding/LLM/全文各选什么？知识库规模多大？

- 问题：检索栈四件——向量（sqlite-vec/pgvector/内存暴力）、embedding（本地 or API、哪家）、LLM（哪家，走 agent-key/Keychain 纪律？）、全文（BM25 手写 or 库）——各选哪档？知识条目预期量级是百、千还是万？
- 为什么问：Owner 只给"RAG/知识库"关键词未给栈与量级；三档现成参照（weknora复刻=sqlite+手写 / WeKnora Lite=sqlite-vec / neo4j-graphrag-ex=Neo4j 系）代价与能力差异大；量级决定"够用"的判定线。
- 影响哪个候选元素：检索问答功能候选的实现形态；图谱构建功能候选（Neo4j 与否）；派生物（向量/倒排/图索引）重建口径。

### Q5 图谱模式层路线：三接入点开哪些？本体先行还是通用清单起步？

- 问题：知识图谱抽取的模式层——(a) 上本体对号表（A 接入点：类型清单=领域本体登记投影）+过闸（B）+前哨（C）全开；(b) 通用清单起步（WeKnora 同款弱模式），疼了再切本体？个人域的"语义错误代价"是否高到值得三接？
- 为什么问：Owner 关键词"本体+建模+知识图谱"隐含本体导向，但个人库要低摩擦快捕获，全量治理与捕获摩擦存在张力（调研 §五）；三接入点投入判据（"语义错误代价越高的域越值得接"，底稿 69）需 Owner 对个人域裁断。
- 影响哪个候选元素：图谱构建功能候选的模式层配置；规则候选（抽取过闸——拦下的边不立边）；语义服务检索瀑布（C 前哨）。

### Q6 Wiki 治理权：LLM 生成页与人工编辑怎么共存？页改动是否回流本体走提案池？

- 问题：Wiki 页面——LLM 自动生成+人工编辑+版本回滚（WeKnora Wiki Mode 全量）要吗？人工编辑过的页面若与本体登记冲突，以谁为准？页改动是否回流本体（走提案池 MR）还是 wiki 自治？
- 为什么问：Owner 给了"wiki"关键词但未给治理口径；TERMS 词条明示"Wiki=无语义治理层"——个人版若要"口径有登记"，wiki 页与本体的主从关系必须裁断，否则出现 ought 双真源。
- 影响哪个候选元素：Wiki 生成功能候选；业务语义循环（提案池）的辖域；本体↔wiki 派生关系（谁是谁的派生物）。

### Q7 消费面：问答从哪进？

- 问题：检索问答/图谱查询的消费入口要哪些——(a) 命令行/脚本；(b) 对话 skill（Kimi Code 路由）；(c) MCP server（外部 agent 消费）；(d) Web UI（含 wiki 浏览）？
- 为什么问：值集类含糊——"管理"未指明消费形态；All-agent 已有 F10 skill 发布器/F11 MCP 发布器现成管线，选哪些决定后端生成器的工作面。
- 影响哪个候选元素：消费面功能候选族；MU/UI 模型候选（是否需要）；MCP 发布候选。

### Q8 书籍管理的粒度到哪？

- 问题：书籍类知识条目管到什么粒度——只管书摘/笔记条目，还是连书籍全文入库+阅读状态（在读/读完/书单）也要？
- 为什么问：Owner 原词"书籍"无粒度；既有资产（书籍资产/ 下是全文 txt，概念资产/ 下是书摘）两种形态并存，装哪个进库直接影响属性面。
- 影响哪个候选元素：知识条目 AGG 候选.书籍类属性候选（全文挂载/阅读状态/书摘关系）。

### Q9 工作业务资料的隐私与敏感边界是什么？

- 问题：公司业务资料入个人库有无合规/隐私红线——是否允许出本机（调云端 LLM/embedding）？要不要敏感度分级与本地处理白名单？
- 为什么问：约束类信息输入未给，但"工作业务"入个人库天然踩公司数据边界；检索栈选型（Q4）与之耦合——敏感约束未定，云端 API 路线不能拍。
- 影响哪个候选元素：规则候选（敏感处理/本地化约束——挂起待口径）；检索栈选型（Q4 的前置）；M5 主体候选（单 Owner，无多主体问题）。

### Q10 捕获链：随手记与结构化入库是一条链还是两条？

- 问题：想法/灵感的快速捕获（随时记、低摩擦）与文档/书籍的结构化入库（解析/分块/抽取管线）是一条管线两个入口，还是两条独立链（捕获区暂存→定期整理入正式库）？
- 为什么问：流程动作只有"管理"一词无触发/前置/状态语义（行为候选挂起纪律）；个人知识库的核心体验恰在捕获摩擦，双链还是单链决定流程模型（M6）与状态机（暂存→整理→入册？）。
- 影响哪个候选元素：行为候选（捕获/入库/整理——挂起待此答）；M6 流程模型候选；知识条目状态属性候选（暂存/入册）。
