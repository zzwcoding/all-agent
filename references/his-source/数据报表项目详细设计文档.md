## 1. 项目概述

### 1.1 项目背景

本项目是为某医院信息系统（HIS）构建的一套**企业级数据报表平台**。平台从底层大数据基础设施搭建起步，完整覆盖数据采集、消息队列、分布式存储、数据仓库分层、离线计算到前端可视化呈现的全链路技术栈，最终以 Web 报表形式为医院管理层提供多维度运营数据分析。

### 1.2 项目目标

1. **数据采集**：将 HIS 业务数据库（MySQL）中的挂号、处方、病历、药品等核心业务数据，通过 DataX 批量同步至 HDFS
2. **数据分层**：按 ODS → DWD → DWS → ADS 标准数仓分层进行 ETL 加工，生成面向分析主题的聚合表
3. **实时日志**：通过 Kafka + Flume 构建业务日志实时采集管道
4. **报表展示**：以 Vue 2 + ECharts 构建 6 大分析主题的可视化仪表盘

### 1.3 技术栈总览

### 3.3 Kafka Topic 设计

| 参数 | 值 | 说明 |
|------|-----|------|
| Topic 名称 | `flume_kafka_topic` | 医院业务日志采集主题 |
| 分区数 | 3 | 对应 3 节点并行消费 |

### 6.3 分层架构

```
Controller (REST 端点)
  │  @Resource 注入 Service
  │  接收请求参数，调用 Service，返回 R<T> 统一响应
  ▼
Service (业务逻辑)
  │  @Resource 注入 Mapper
  │  调用 MyBatis-Plus QueryWrapper 构造查询条件
  ▼
Mapper (数据访问)
  │  7 个 Mapper → his-report 默认数据源
  │  2 个 Mapper → @DS("his") 指向 HIS 源库
  ▼
MySQL 数据库
```

### 6.5 双数据源配置

```yaml
spring:
  datasource:
    dynamic:
      primary: his-report                         # 默认主数据源
      datasource:
        his-report:
          url: jdbc:mysql://192.168.100.200:3306/his_report_db
          username: root
          password: Root@123456
        his:
          url: jdbc:mysql://192.168.100.200:3306/his
          username: root
          password: Root@123456
```

- 未标注 `@DS` 的 Mapper 自动使用 `his-report` 主数据源
- `DiseaseMapper` 和 `RegisterMapper` 标注 `@DS("his")` 指向 HIS 源库
- MyBatis-Plus 配置：下划线自动转驼峰，SQL 日志输出

### 8.2 院长驾驶舱接口

#### GET /api/v1/dashboard/kpi

- **说明**：获取核心 KPI 卡片数据（最新一天）
- **参数**：无
- **SQL**：
  ```sql
  SELECT * FROM his_report_db.ads_dashboard_kpi ORDER BY visit_day DESC LIMIT 1;
  ```
- **返回**：DashboardKpi 对象

#### GET /api/v1/dashboard/trend

- **说明**：近 7 日接诊趋势
- **参数**：无
- **SQL**：
  ```sql
  SELECT visit_day, register_cnt, register_revenue
  FROM his_report_db.ads_dashboard_kpi
  ORDER BY visit_day DESC LIMIT 7;
  ```
- **返回**：`List<DashboardKpi>`（仅含 visitDay, registerCnt, registerRevenue）

#### GET /api/v1/dashboard/payment

- **说明**：支付方式分布
- **参数**：无
- **SQL**：
  ```sql
  SELECT regist_method, SUM(revenue) AS revenue
  FROM his_report_db.ads_revenue_payment
  GROUP BY regist_method
  ORDER BY revenue DESC;
  ```
- **返回**：`List<Map<String, Object>>`（registMethod, revenue）

### 8.3 门诊运营接口

#### GET /api/v1/outpatient/dept-rank

- **说明**：科室接诊量排行
- **参数**：`startDate` (yyyy-MM-dd), `endDate` (yyyy-MM-dd)
- **SQL**：
  ```sql
  SELECT dept_name,
         SUM(total_visits) AS total_visits,
         SUM(refund_count) AS refund_count,
         ROUND(SUM(refund_count)*100.0/SUM(total_visits), 2) AS refund_rate
  FROM his_report_db.ads_dept_visit_rank
  WHERE visit_day BETWEEN #{startDate} AND #{endDate}
  GROUP BY dept_name
  ORDER BY total_visits DESC;
  ```

#### GET /api/v1/outpatient/doctor-rank

- **说明**：医生接诊量 TOP15
- **参数**：`startDate`, `endDate`
- **SQL**：
  ```sql
  SELECT doctor_name, dept_name, SUM(visit_count) AS visit_count
  FROM his_report_db.ads_doctor_visit_rank
  WHERE visit_day BETWEEN #{startDate} AND #{endDate}
  GROUP BY doctor_name, dept_name
  ORDER BY visit_count DESC
  LIMIT 15;
  ```

#### GET /api/v1/outpatient/status-flow

- **说明**：就诊状态流转（漏斗图）
- **参数**：无
- **SQL**：
  ```sql
  SELECT CASE visit_state
    WHEN 1 THEN '已挂号'
    WHEN 2 THEN '医生接诊'
    WHEN 3 THEN '看诊结束'
    WHEN 4 THEN '已退号'
  END AS state_name,
  COUNT(*) AS cnt
  FROM his.register
  GROUP BY visit_state;
  ```

### 8.4 收费结算接口

#### GET /api/v1/finance/revenue-trend

- **说明**：每日挂号收入趋势
- **参数**：`startDate`, `endDate`
- **SQL**：
  ```sql
  SELECT visit_day, SUM(total_revenue) AS daily_revenue
  FROM his_report_db.ads_dept_visit_rank
  WHERE visit_day BETWEEN #{startDate} AND #{endDate}
  GROUP BY visit_day
  ORDER BY visit_day ASC;
  ```

#### GET /api/v1/finance/payment-ratio

- **说明**：支付方式收入占比（含子查询计算占比）
- **参数**：`startDate`, `endDate`
- **SQL**：
  ```sql
  SELECT regist_method, SUM(revenue) AS revenue,
         SUM(revenue)*100.0 / (
           SELECT SUM(revenue) FROM his_report_db.ads_revenue_payment
           WHERE visit_day BETWEEN #{startDate} AND #{endDate}
         ) AS revenue_pct
  FROM his_report_db.ads_revenue_payment
  WHERE visit_day BETWEEN #{startDate} AND #{endDate}
  GROUP BY regist_method
  ORDER BY revenue DESC;
  ```

#### GET /api/v1/finance/dept-avg-fee

- **说明**：各科室均次费用
- **参数**：`startDate`, `endDate`
- **SQL**：
  ```sql
  SELECT dept_name,
         SUM(total_revenue) / SUM(total_visits - refund_count) AS avg_fee
  FROM his_report_db.ads_dept_visit_rank
  WHERE visit_day BETWEEN #{startDate} AND #{endDate}
  GROUP BY dept_name
  ORDER BY avg_fee DESC;
  ```

### 8.6 疾病诊断接口

#### GET /api/v1/disease/diag-top20

- **说明**：诊断疾病 TOP20（关联疾病字典取中文名）
- **参数**：无
- **SQL**：
  ```sql
  SELECT d.disease_name, COUNT(mrd.disease_id) AS diag_cnt
  FROM his.medical_record_disease mrd
  JOIN his.disease d ON mrd.disease_id = d.id
  GROUP BY d.disease_name
  ORDER BY diag_cnt DESC
  LIMIT 20;
  ```

#### GET /api/v1/disease/icd-dist

- **说明**：ICD-10 疾病章节分布（按首字母分章）
- **参数**：无
- **SQL**：
  ```sql
  SELECT LEFT(d.diseaseICD, 1) AS icd_chapter, COUNT(*) AS cnt
  FROM his.medical_record_disease mrd
  JOIN his.disease d ON mrd.disease_id = d.id
  WHERE d.diseaseICD IS NOT NULL AND d.diseaseICD != ''
  GROUP BY LEFT(d.diseaseICD, 1)
  ORDER BY cnt DESC;
  ```

#### GET /api/v1/disease/record-complete

- **说明**：病历完整率（主诉/现病史/既往史/过敏史/体格检查 5 个维度）
- **参数**：无
- **SQL**：
  ```sql
  SELECT COUNT(*) AS total,
    SUM(CASE WHEN readme IS NOT NULL AND readme != '' AND readme != '未填写' THEN 1 ELSE 0 END) AS has_readme,
    SUM(CASE WHEN present IS NOT NULL AND present != '' AND present != '未填写' THEN 1 ELSE 0 END) AS has_present,
    SUM(CASE WHEN history IS NOT NULL AND history != '' AND history != '未填写' THEN 1 ELSE 0 END) AS has_history,
    SUM(CASE WHEN allergy IS NOT NULL AND allergy != '' AND allergy != '未填写' THEN 1 ELSE 0 END) AS has_allergy,
    SUM(CASE WHEN physique IS NOT NULL AND physique != '' AND physique != '未填写' THEN 1 ELSE 0 END) AS has_physique
  FROM his.medical_record
  WHERE delmark = 1;
  ```

### 8.7 患者画像接口

#### GET /api/v1/patient/age-pyramid

- **说明**：年龄-性别金字塔（5 个年龄段 × 性别交叉统计）
- **参数**：无
- **SQL**：
  ```sql
  SELECT CASE
    WHEN age BETWEEN 0 AND 18 THEN '0-18岁'
    WHEN age BETWEEN 19 AND 35 THEN '19-35岁'
    WHEN age BETWEEN 36 AND 50 THEN '36-50岁'
    WHEN age BETWEEN 51 AND 65 THEN '51-65岁'
    ELSE '66岁以上'
  END AS age_group, gender, COUNT(*) AS cnt
  FROM his.register
  WHERE age IS NOT NULL
  GROUP BY age_group, gender
  ORDER BY age_group, gender;
  ```

#### GET /api/v1/patient/region-dist

- **说明**：患者地域分布 TOP10
- **参数**：无
- **SQL**：
  ```sql
  SELECT home_address AS region, COUNT(*) AS cnt
  FROM his.register
  WHERE home_address IS NOT NULL AND home_address != '未知'
  GROUP BY home_address
  ORDER BY cnt DESC
  LIMIT 10;
  ```

#### GET /api/v1/patient/revisit-rate

- **说明**：复诊率统计
- **参数**：无
- **SQL**：
  ```sql
  SELECT COUNT(DISTINCT case_number) AS total_patients,
         COUNT(*) AS total_visits,
         COUNT(*) - COUNT(DISTINCT case_number) AS revisit_visits,
         ROUND((COUNT(*)-COUNT(DISTINCT case_number))*100.0/COUNT(*), 2) AS revisit_rate
  FROM his.register;
  ```

## 10. 核心业务流程

### 10.1 离线数据管道（T+1 批量处理）

```
步骤 1: DataX 全量抽取
  MySQL his 库的 15 张表 → HDFS /data/xxx_mysql/ 目录 (CSV)

步骤 2: Hive 建外部表
  CREATE EXTERNAL TABLE ods_db.xxx (...) LOCATION '/data/xxx_mysql/'

步骤 3: Hive ETL 加工
  ODS → DWD: 清洗空值、标准化编码、字段拆分、派生字段
  DWD → DWS: 按天/科室/医生/支付方式聚合
  DWS → ADS: 生成 7 张最终报表聚合表

步骤 4: ADS 写回 MySQL
  ADS 结果 INSERT 到 his_report_db 对应表

步骤 5: 报表 API 查询
  Spring Boot → MyBatis-Plus → his_report_db → 返回 JSON
```

### 10.2 实时日志管道

```
步骤 1: HIS 业务系统产生日志 → Kafka Producer 发送
步骤 2: Kafka Broker (3节点, 3分区) 接收并持久化
步骤 3: Flume Consumer (flume-consumer-group) 消费 → Memory Channel → HDFS Sink
步骤 4: 日志按日期分区写入 HDFS: /flume/flume/kafka/YYYYMMDD/
```

### 10.3 前端数据加载流程

```
页面 mounted()
  │
  ├── 调用 API 函数 (api/index.js)
  │      │
  │      └── request.js (Axios 实例)
  │             │ baseURL: /api/v1
  │             │ 代理 → http://localhost:8080
  │             │
  │             ▼
  │        后端 Controller
  │             │
  │             ▼
  │        Service
  │             │ MyBatis-Plus QueryWrapper
  │             ▼
  │        Mapper (@DS 决定数据源)
  │             │
  │             ▼
  │        MySQL (his_report_db / his)
  │
  ├── 填充 KPI 数据到响应式 data
  │
  └── $nextTick() → 初始化 ECharts
       │
       └── this.$echarts.init(this.$refs.chartN)
           └── chart.setOption({...})
```

## 12. 性能与安全

### 12.1 性能优化措施

| 层级 | 策略 | 说明 |
|------|------|------|
| 数据层 | ADS 预聚合 | 计算密集型操作在 ETL 阶段完成，API 只读现成表 |
| 数据层 | 数据分层 | ODS→DWD→DWS→ADS，逐层细化，减少重复计算 |
| 后端 | 连接池 | 使用 HikariCP（Spring Boot 默认），复用数据库连接 |
| 后端 | 双数据源 | his_report_db 专用于报表查询，不影响业务库性能 |
| 前端 | 懒加载路由 | 6 个页面按需加载，减少首屏体积 |
| 前端 | 响应式 | 1400px 断点自动切换 3 列/1 列布局 |
| 消息队列 | 3 分区并行 | Kafka 3 分区对应 3 节点并行消费，提升吞吐 |

### 12.2 安全配置

| 措施 | 位置 | 说明 |
|------|------|------|
| CORS 跨域 | CorsConfig.java | 开发环境全部放通，生产环境需限制来源 |
| 参数校验 | FilterBar.vue | 前端校验日期范围完整性，防止空参数请求 |
| SQL 参数绑定 | MyBatis `#{}` 占位符 | 防止 SQL 注入 |
| 异常处理 | Axios 拦截器 | 统一捕获网络和业务异常并日志输出 |
| 数据库密码 | application.yml | 当前为明文 Root@123456，生产环境需改为环境变量或配置中心管理 |

### 12.3 已知待优化项

1. **硬编码日期**：部分 API 调用在前端写死日期范围（如 Drug.vue 的 `{startDate:'2022-06-01', endDate:'2022-06-10'}`），应统一由 FilterBar 管理或改为动态默认值
2. **SQL 注入风险**：`FinanceService.getPaymentRatio()` 中使用了字符串拼接 `...'" + startDate + "'...` 构造子查询，建议改用 MyBatis 参数绑定
3. **分页缺失**：所有列表接口均无分页参数，数据量增长后需添加
4. **缓存缺失**：无 Redis 缓存层，高频查询的 KPI 数据直接查询数据库
5. **认证授权**：当前无用户登录/权限控制
6. **单元测试**：仅有空的上下文加载测试，需补充 Service 和 Mapper 层测试

## 附录：技术决策记录

| 决策项 | 选择 | 原因 |
|--------|------|------|
| 后端框架 | Spring Boot 3.3.5 (非 2.7.x) | 使用最新 LTS 版本，Java 17 基线 |
| ORM | MyBatis-Plus (非 JPA) | 更灵活的原生 SQL 控制，适合报表查询场景 |
| 多数据源 | dynamic-datasource (非手动配置) | 注解式切换，代码侵入性低 |
| 前端框架 | Vue 2 (非 Vue 3) | 兼容 Element UI，降低迁移成本 |
| 图表库 | ECharts (非 Chart.js) | 支持更丰富的图表类型（漏斗图、矩形树图、雷达图） |
| 端口规划 | 后端 8080, 前端 8081 | 避免与 Hadoop/YARN/Spark Web UI 端口冲突 |
| 副本因子 | 2 (非 3) | 3 节点集群中 3 副本无法均匀分布，2 副本保证可用 |
| 数据分层 | ODS→DWD→DWS→ADS 四层 | 行业标准分层，便于数据质量追溯和复用 |
| 前端设计 | 自建设计 Token (非 UI 框架主题) | 更精确的医疗行业品牌调性控制 |
