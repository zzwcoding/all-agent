## What to build

- 孤儿 skill 检测（--check 报"仓内已删、安装位还在"）+ `--prune` 清除

## 设计裁决（L0 已定）

- **钩子方案走 `core.hooksPath`**：git 钩子默认不随 clone 走，落闸的正确姿势=仓内提交 `tools/hooks/pre-commit`（可执行）+ AGENTS.md 续跑协议加一行一次性 setup 指令（`git config core.hooksPath tools/hooks`）。施工时把**本仓本地** git config 设好并验证（这是本机可逆配置，允许动），其他 clone 靠协议行。
- **钩子内容极简**：只跑 `python3 tools/install_skills.py --check`，非零即拒绝提交并在 stderr 提示跑 sync；不塞其他检查（四闸已有 ci.sh，钩子只管安装位漂移这一件高频踩的事）。空 `skills/` 差异时快速通过。
- **孤儿检测走注册表文件** `tools/install-registry.json`（sync 时写入本仓管理的 skill 名清单；--check 对照：安装位存在、注册表登记、仓内正本已删 → 报 orphan；`--prune` 删之）。marker 文件方案否决——会污染安装位目录、干扰 diff。注册表进归档闸受管（tools/*.json——若布局表 tools 只收 *.py/*.sh，则按既有惯例改放 references/ 或扩布局表 patterns，施工时按归档闸实测抉择并记录）。
- **symlink 设防**：正本或安装位的 skill 目录若为符号链接，sync/--check 一律报错拒处理（`config-error` 退出码 2），不做递归解析——防路径逃逸。
