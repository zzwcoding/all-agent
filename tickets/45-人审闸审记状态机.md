## What to build

`tools/review_gate.py` 四动作 CLI（照 --check 家族惯例）：

1. **init**：为目标生成物建审记旁档骨架（`exports/reviews/<生成物>-review.json`，逐版本追加不覆盖）。
2. **approve**：写入审记 `{target, reviewedCommit, reviewedSha256, verdict: 已审, checkpoints[], notes, reviewedBy, date}`——reviewedSha256 现算目标文件；reviewedCommit 取 git HEAD。
3. **reject**：verdict=打回 + 强制 `routing` 字段（业务错道提案池 / 工程错道 tickets，含单号指针）——裁决点 6：打回必须当场开单，不允许只记意见。
4. **verify**：现算目标 sha256 与最新有效审记比对——不一致（生成物再生过）报失效回落待人审；无审记/审记损坏按待人审处理（缺失=无效，宁多审一次；不重建审记，design §3.4 #2）。

退出码契约：0 一致（已审且哈希匹配）/ 1 失效或缺失 / 2 配置错。

specs/archive-registry.json 登记新产物类 **review-record**（照票 37 给 devkit/skillpack 登记的先例，requiredFields 实跑驱动收敛）。

## 设计裁决（L0 已定）

- 生成物本体一字不动：审记旁档是唯一载体；status 行字面和归档闸既有契约零改动（design §5 不做 5）。
- 失效严格度 = 零宽限：哈希不一致即失效（裁决点 5）。
- verdict 词汇用二元（已审/打回），不自造第三套词（design §4 统一结论词汇）。
- 随票定：reviewedBy 形式（design 开放问题③）——倾向 git 身份（`git config user.name`），施工时确认并写进 specs。
