## What to build

`tools/l5_score.py` CLI——L5 评分面的确定性部分（LLM 评分由运行时子 agent 产出评分结果 JSON，本脚本只消费不落模型调用）：

1. **rubric 格式校验**：rubric 文件（fixtures/semantic-service/rubrics/，票 43 填充；本票出厂集自带样例）缺锚定例（每维 5/3/1 分档 anchors 必填）/ 权重非法（非正整数）/ reference 指向的参照答案不存在 → 红。
2. **评分结果文件校验**：子 agent 产出的评分 JSON 必须严格合法——维度与 rubric 对齐、分数 0–5 整数、逐问逐维齐全；脏数据（多说废话/漏维/越界分）判"评分无效"（exit 2 类配置错口径），不进入聚合。
3. **聚合与判定**：每问 3 采样取中位；3 采样分差 ≥2 标"不稳定"；disqualifier 触发 = 该问 0 分一票否决；通过线 = 单问总分 ≥3 且全集中位 ≥4.0 且无 0 分（design §4.2），三条同时满足才绿。
4. **报告落盘**：`docs/meta/l5-评分-<日期>.md` + 同名 .json 机读伴生（同名加序号后缀不覆盖，照 meta_probe 体检留痕惯例）；内容 = 每问逐维分数 + 采样分布 + 结论 + 红灯路由去向。
5. **退出码契约**：0 绿 / 1 红（低于通过线或触发 disqualifier）/ 2 配置错（rubric 非法、评分文件无效）。

## 设计裁决（L0 已定，施工即照此）

- 评分请求/结果 JSON 协议本票成文（落 specs/l5_score.md）：请求 = {question, reference_answer_path, candidate_answer_path, rubric_path}；结果 = {question_id, dimensions: [{id, score, reason}], disqualifier_triggered: bool}。票 44 的子 agent 派发契约以此为准。
- 评分提示词载体：随 rubric 进 fixtures（design 开放问题④已随票定为此——提示词改 = 改出厂集 = 走票）。
- mock 注入 = 预置评分结果 JSON 文件（出厂集内），脚本从文件读，无任何模型 client。
- 归档闸若拦 docs/meta/l5-评分-* 新形态，照体检留痕同款式样登记/对齐布局表。
