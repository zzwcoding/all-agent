## 设计裁决（L0 已定）

- **模式件文件约定**：`ontology/patterns/<pattern-id>.yaml`，头字段 `pattern_id / name / description / applies_when（适用信号）/ fragment（可组合 YAML 片段，元素带 `{{占位符}}`）/ compose_notes（组合与改名列注意）/ source`（首批 source=L0 授权自创，票 33）。首批 5 件：**状态机生命周期**（lifecycle+status 字典组合）、**主从聚合**（一对多聚合+从表外键引用）、**编码字典**（DictionaryRef 属性+字典条目）、**有效期版本**（元素级 validFrom+停用不删除组合）、**审批流**（APPROVAL_TASK 活动+角色 roleRef 组合）。
- **组合产物纪律**：模式件不是本体——组合进草案时必须（a）占位符全部替换为域实例（b）pattern_id 写进元素 description 注记"组合自 patterns/<id>"（c）产物仍是草案走人审。这条进 onto-modeler 的 SKILL.md 工序（步骤 2.5：脚手架前后查 patterns/ 匹配 applies_when）与 references/profile-selection 或新 references/pattern-usage.md。
- **机判面**：模式件文件结构断言（YAML 可解析+头字段齐+fragment 可被 yaml 解析+占位符形如 {{xxx}}）走 fixtures/pattern-library/ 的 cmd/file 断言；**组合示例机判**：fixtures 内放一个"组合示例域"（从两件模式组合出的迷你草案，占位符已替换、含 pattern 注记）过 schema_check L1——证明"模式件→草案"通路真实可走。
- **边界**：patterns/ 是素材不是域——不进 schema_check 域校验（无 manifest），由本票出厂集断言承载结构纪律；归档闸由 layout patterns 覆盖（ontology 条目 patterns ["**"] 已收，实测确认）。
