## 设计裁决（L0 已定）

- **件一（干净失败）**：装配口径卡时 `QR.behaviorRef` 等键缺失不再 KeyError 裸崩——捕获后走结构化配置错误（exit 2，stderr 报"域内 M7 元素 <id> 缺 behaviorRef 键（装配口径卡需要）——先过 schema_check（required-field）"），不产残包文件。语义口径：schema_check 是字段完备的第一道闸，生成器遇残缺输入一律干净拒绝而非部分输出。负变体：域副本剃 behaviorRef → exit 2 且 stderr 含定位、无输出文件；既有正常路径零改动。
- **件二（常数化）**：semantic_service_core.py 顶部新增公开常量 `WATERFALL_STEPS`（四步路由的 (编号,名称,一句话) 元组列表——与 core 实现的同名工序一一对应，docstring 声明"瀑布真源常量，工序/文档/发布物三处消费"）；skill_pack_gen 改为 import 该常量渲染工序路由节（不再自有静态文本）；单测钉"渲染输出包含常量全部步骤名"（瀑布演进改常量→测试提醒三处同步）。**注意**：skill_pack_gen 目前零 import core——本票建立该 import（仅常量，无逻辑耦合），lessons 记这是观察项 #1 的既定清偿方向。
- 既有断言零倒（两生成器黄金包不受影响——渲染结果若与入库副本有差异，属常数化文案变化，须同步重 gen 入库副本并在 lessons 说明 diff）。
