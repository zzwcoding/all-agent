## 可机判子集清单（L0 裁决——本票设计节，施工即照此）

L3 五级语义=指标/SQL/安全。本票只收**确定性可判子集**，四项：

| # | 检查 | 判定 | 违规码 |
|---|---|---|---|
| L3-1 | M3 规则 sourceField 字段存在性 | 规则参数 `sourceField` 双段（对象.属性）：对象段解析到域内聚合（id/name 匹配）、字段段在该聚合 attributes 中存在 | `l3-source-field` |
| L3-2 | M7 口径表达式引用可解析 | query_reports 的 `sourceObjects[].alias` 与 `resultColumns[].sourceExpression` 引用一致：表达式内 `别名.字段` 的别名必须已声明、字段必须在该别名所指聚合的属性中 | `l3-expression-ref` |
| L3-3 | M7 referenceSql 只读性 | referenceSql（可选字段）在场即扫：必须 SELECT 形态，DML/DDL 黑名单词（INSERT/UPDATE/DELETE/DROP/ALTER/TRUNCATE/CREATE/GRANT）出现即红 | `l3-sql-readonly` |
| L3-4 | M3 规则形态完备性 | ruleType=EXPRESSION → expression 在场；narrative 型 → narrative 在场（二选一落地的机判面——票 13 缺口清单登记项） | `l3-rule-form` |

**明示不收**（防子集蔓延）：SQL 语义正确性（需执行环境）、指标公式数学正确性（Owner 裁决域）、安全敏感度分级（需口径）、任何需 LLM 判断的项——留给 L5 设计案（批次三方案 1）。

## 设计裁决（L0 已定）

- 四项检查如上清单，全部纯机读（YAML 字符串/结构解析，零执行环境零 LLM）。
- L3-1/L3-2 的"对象.属性"解析基准：聚合匹配按 id 或 name（与 core 解析口径一致）；字段在该聚合 attributes[].name 集合内。解析不了的段（如对象段悬空）报本码并附定位——悬空 ID 本身另有 dangling-ref，红因不混。
- L3-3 黑名单大小写不敏感、词边界匹配（防 UPDATE出现在列名误伤——用 `\b` 边界）。
- 报告结构：L3 加入现有 L1/L2/L4 计数行（`L1: x | L2: x | L3: x | L4: x`），--json 同步。
