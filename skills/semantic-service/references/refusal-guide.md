# 拒答话术与缺件说明规范（semantic-service · 域无关）

可拒答是本服务的交付能力之一：拒答不是失败，是「没有证据就不出口」的纪律。本文固定话术结构，全文域无关。

## R1 · 检索面外（camp=build-contract）

必含四件（缺一不算合格拒答）：

1. **结论先行**：明确「不在检索面/不属于本服务回答范围」，不返回该元素任何细节（名称、布局、控件、动作、菜单一概不给）；
2. **阵营归属说明**：按注册表说明其 camp（如「属界面模型，camp=build-contract」）；
3. **保留锚定**：可复述用户给的锚定 ID 本身（那是用户输入，不是检索产出）；
4. **指路**：建造契约由 build 侧消费方在建造链路消费；若属业务语义缺口，走提案流程。

可选加分：给服务面内的**等价业务概念**（真实存在、带 ID），但必须注明是「业务面等价概念」而非该元素的映射关系——映射本身可能属面外模型，不得代答。

## R2 · 仓内没有

必含四件：

1. **结论先行**：「仓内没有该概念」，直接说没有，不用「可能/大概」；
2. **检索轨迹**：一句话交代查了什么（名称候选、ID 复核未找到不猜），证明穷尽而非遗漏；
3. **缺什么（缺件分层说明）**：按 查询层（缺统计/报表）→ 对象/字段层（缺承载概念）→ 行为/规则层（缺动作/校验）逐层核对，只声明真缺的层；
4. **下一步**：业务口径缺口 → 走提案流程补定义（进仓走 MR + 语义 CI）；本服务只读不代填。

近邻指路规则：至多给最接近的 1–2 个真实概念，必须（a）真实存在带 ID，（b）标注「近邻，非所问」，（c）不借近邻暗示仓内已有答案。

## R3 · 锚定/解析失败

锚定 ID 不存在或名称解析穷尽未命中时，话术并入 R2，检索轨迹注明「锚定 ID 未找到，不猜」。禁止：猜近似拼写 ID；给「你是不是想要 X」式臆测命中（给候选必须标注「未验证，请锚定」）。

## R4 · 写意图

固定话术：改口径/补概念/修模型请走提案流程（进仓走 MR + 语义 CI）；本服务只读，不产文件、不改仓。可以附缺件/建议内容，但不得携带「我已替你改好」式暗示。

## 通用禁则

- **不编造 ID**：答案中出现的每个 ID 都必须是检索产出或用户输入；
- **不给无锚定论断**：每个业务论断标注承载 ID（格式见 references/id-citation-format.md）；
- **不把「相似」当「命中」，不把「没有」答成「有但……」**；
- **拒答也要带 ID**：R1 复述锚定 ID，R2 近邻指路带 ID——空手拒答不是合格拒答。
