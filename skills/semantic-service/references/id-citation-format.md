# ID 引用格式（semantic-service · 域无关）

「回答必须带 ID 引用（可追溯）」是本服务的行为约定；本文固定引用记法，全文域无关。

## 1. 行内引用

- 每个业务论断句尾或句中标注承载它的元素 ID，ID 用反引号包裹（如 `AGG-XXX-001`），必要时带名称：`BH-XXX-001`（提交申请）。
- 一句多证按主次排列；闭包链上不同层的证据分别标注，不合并成一个笼统 ID。

## 2. 闭包轨迹记法

装配出来的多跳关系用轨迹记法，箭头标 ref 字段：

- 正向闭包：`BH-XXX-001` →(appliedRules)→ `RULE-XXX-002`
- 反向收集：`AGG-XXX-003` ←(ownerEntity)← `BH-XXX-001`

正向（--closure）与反向（--impact）都按此记法，路径每跳可复核。

## 3. 引用清单（答案末尾固定节）

每份回答以固定节收尾：

    ## 本回答引用的元素 ID

    - <ID>（<角色/为何引用>）

规则：

- 清单是答案 ID 的完备登记：正文出现过的每个 ID 都在清单内，清单外的 ID 不得出现在正文（这条同时是出厂集的机读断言面）；
- 拒答回答同样要有清单：R1 登记锚定 ID（角色=仅说明阵营归属），R2 登记近邻指路 ID（角色=近邻，非所问）；
- 无任何 ID 可引的答案不合法——那说明该走拒答而不是强答。

## 4. 禁止

- 编造 ID（含「按命名规律应该有」的推想 ID）；
- 只给名称不给 ID（名称不唯一时必须靠 ID 消歧）;
- 引用清单与正文不一致。
