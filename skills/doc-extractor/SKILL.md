# doc-extractor · 文档萃取（L1 工序，前端适配器）

把制度/规范/设计类成文文档变成结构完备、能过语义闸的本体**草案**——文档的本体形态就是术语与规则（GLS 术语条目 + M3 规则条目为主），外加一份**证据索引**（每条候选 → 文档 file#锚点 逐条证据），自下而上供业务 Owner 裁决。本 skill 机器通用：正文不含任何具体业务域知识，域素材只存在于出厂集与用户提供的输入里。

## 触发面 / 何时用

- 用户要「从这些文档萃取概念/术语/规则草案」时使用。
- 不适用：从粗需求正向收敛（输入是粗素材、要反问收敛，那是同族另一道上游工序的事）；从库表/DDL 或源码逆向成本体（同族另两道前端适配工序的事）；改已定稿本体（写入必经 MR，本 skill 只产草案不进仓）；运行期查询口径（那是运行时服务的事）。

## 输入输出契约

- reads：用户提供的成文文档/资料库（采信范围见 references/extraction-guide.md §1——术语定义句、可条件化条款、状态声明（废弃/限语境）、文档自带编号结构）；`ontology/schema/**`（schema 文档与两份机读表：模型注册表、依赖白名单）。
- writes：`ontology/<域>/**` 草案——域 manifest.json + 有证据的模型文件（GLS 术语 + M3 规则为主；零证据的整模型挂 manifest omittedModels 带理由豁免，不产空壳文件）；`docs/doc-extractor/<域>-证据索引.md`——候选清单（逐条注源+状态判定）+疑点清单+状态标注留痕，末节覆盖对照表。只产草案，进仓走 MR。
- 依赖脚本：`tools/schema_check.py`（语义闸，修整步的判定器）。

## 工序（按序执行，每步产物落盘）

1. **输入清点与标记条目清单落盘**：通读文档，把定义句/条款逐条登记成标记条目清单（编号+类型 术语/规则/叙述+锚点；锚点=文件#条目号，文档无自带编号的按稳定顺序补号）——这是覆盖不变量的输入侧，清单与文档对不上，后面全部白做。
2. **定义句/条款抽取映射**：按 references/extraction-guide.md §2 总表逐条映射——定义句→GLS 术语候选、可条件化条款（IF/超限/必填形态）→M3 规则候选；每条候选注源 `文档 file#锚点`，映射不出处即发明语义。
3. **状态判定与三落点判定**：文档明示废弃/仅限某语境的条目照 GLS status 纪律如实标注（废弃注替代口径、限语境注语境），不洗白不静默丢弃；逐条判定落点（判定树见 guide §3/§5）——判据齐可复述→草案元素候选；纯叙述性/含糊（无可判定条件与阈值）→疑点清单，不硬转规则；噪声（背景铺垫/行政叙事）→明示不萃取清单（带理由）。**宁可挂起不可硬建**。
4. **生成草案+证据索引**：按 schema 公共字段与 ID 前缀约定落 GLS/M3 模型 YAML + manifest.json——文档的本体形态就是术语与规则，默认不产 M1/M2 文件（零对象/行为/主体/界面证据的挂 omittedModels 带理由豁免；relatedObjectRefs 无承载不硬挂，规则 inputParams 不写 sourceField）；草案头部固定声明「证据非权威，待 Owner 确认」。证据索引落候选清单（逐条注源+状态判定）+疑点清单（四要素）+状态标注留痕，末节覆盖对照表（标记×落点，反引号只锚定首列编号）。
5. **覆盖不变量自检**：标记条目清单 ×（证据索引末节覆盖对照表）双向核对，逐条确认落点——任何一条两处皆无 = 漏覆盖，回步骤 3，不许带漏交付。出厂集探针是本步的机判参照实现。
6. **修整过语义闸**：跑 `python3 tools/schema_check.py <域目录>`，按报告逐条修复直到全过。本 skill 不做 git 提交、不直改已定稿本体。
7. **交 Owner 裁决**：交付时明示——草案与证据索引全部为证据面，术语取舍/状态终判/规则条件化/口径占位均「待 Owner 确认」；疑点清单是给 Owner 的提问清单；Owner 裁决后按 MR 流程进仓。

## 行为约定

- **草案头部固定声明「证据非权威，待 Owner 确认」**；交付物不得作为已定稿本体消费。
- **状态不洗白**：文档明示废弃/仅限某语境的条目必须萃取且 status 如实标注（照 GLS status 纪律，废弃条目注替代口径），不得洗白成无限定的有效术语，也不得静默丢弃——旧称与限语境词本身是治理事实。
- **规则必须条件化**：IF…THEN 可判定形态（含超限/必填）才立 M3 候选；纯叙述性条款（应加强/应推进类，无可判定条件与阈值）进疑点清单不硬转——强转即发明语义。
- **每条候选注源 `文档 file#锚点`**；引用与字段承载零证据零登记（relatedObjectRefs 不硬挂、sourceField 不硬指）。
- **疑点不静默吞掉**：叙述性条款、含糊限定词、口径冲突、重复定义、状态缺失逐条登记（锚点+原文+特征+待 Owner 问题）并回写证据索引——宁可多报不可漏报。
- **AI 只做格式转换与结构完备性**：业务语义（术语取舍、口径、状态终判、规则条件化）必须人确认。

## 出厂集（Seam）

`fixtures/doc-extractor/`——合成制度文档两份（中性域：术语定义段含明示废弃与明示限语境条目，规则条款段含可条件化条款与纯叙述性条款）→ 断言草案过语义闸+萃取覆盖探针正例 exit 0（AC1）、草案头部声明与 file#锚点 注源+证据索引 ≥7 条且逐条含锚点（AC2）、覆盖对照表缺一条的负变体 exit 1（AC3）。改本 skill 工序描述前，先确认出厂集仍绿。
