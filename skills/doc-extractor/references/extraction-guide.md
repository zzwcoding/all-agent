# 文档萃取指导书（doc-extractor 细则）

> 全文域无关：只定义「从成文文档到本体草案与证据索引」的转换规则，不含任何具体业务域知识。
> 与 schema 真源冲突时 schema 赢、回改本指南；schema 查什么见 SKILL.md 输入输出契约中的
> `ontology/schema/**`（人读总纲 + 两份机读表）。GLS 条目结构与 status 纪律以仓内既有
> 术语模型与 schema 为准；M3 字段口径以 schema 规则模型节为准。

## 1. 输入形态、采信范围与锚点纪律

### 1.1 输入三类

1. 制度/规范/管理办法类文档（条款化行文：术语定义段 + 条款段）；
2. 设计/方案类文档（含术语表、约束描述）；
3. 文档目录（多文件资料库，逐文件处理，跨文件同概念互证）。

### 1.2 采信范围（证据只有这些）

- 术语定义句：「X：……」「X 指……」「X 是……」形态的成段定义；
- 规则条款句：可条件化的约束——IF…THEN 型、超限判定型、必填要求型、阈值明文型；
- 状态声明：文档对条目自身的裁决——明示废弃（含替代口径）、明示仅限某语境、明示待定；
- 文档自带的条目编号与小节结构（锚点位）。

### 1.3 不采信

- 流程叙事、组织介绍、背景铺垫（不单独立元素）；
- 从措辞引申的「行业惯例」语义；
- 文档没写的口径按「待 Owner 确认」占位，不脑补。

### 1.4 锚点纪律

- 锚点格式：`文件名#条目号`；条目号用文档自带编号，无编号按稳定顺序补号并在清单头部注明补号规则。
- 每条候选/疑点/对照行必须可回指：拿到锚点能在文档里指认原句——指认不了 = 无效注源，等于没注。

## 2. 映射总表

| 文档形态 | 映射目标 | 立候选的最低证据 | 证据不足时 |
|---|---|---|---|
| 术语定义句 | 术语候选（GLS terms） | 成段定义句+状态可判 | 定义含糊→疑点清单，不硬收 |
| 可条件化条款 | 规则候选（M3 rules） | 条件+判据（IF/超限/必填/阈值）齐 | 只有结论无判据→疑点清单 |
| 状态声明（废弃/限语境） | GLS status 字段 | 文档明文 | 文档未声明→status「有效」，不臆测 |
| 叙述性条款（应加强/应推进） | 疑点清单 | ——（无可判定条件与阈值） | 永不硬转规则 |
| 噪声（背景/行政/排版残句） | 明示不萃取清单 | —— | 带理由显式留痕 |

映射纪律：每条候选注源 `文档 file#锚点`；映射不出处即发明语义。注源是「AI 只做格式转换」的可审计面。

## 3. 术语萃取细则（GLS）

- 定义句**直译**进 definition，不改写口径、不增删限定——改写即替 Owner 下结论。
- termType 按文档证据判（普通术语/口径词/别名/缩写/禁用词……照仓内既有域惯例取值）；
  aliases 只收文档明示的同义/旧称对应，不猜。
- **状态标注纪律（不洗白）**：明示废弃 → status「废弃（替代：X）」，替代口径照文档原文注；
  明示仅限某语境 → status「有效（限 X 语境）」；未声明 →「有效」。废弃与限语境是治理事实，
  洗白成无限定的有效术语与静默丢弃都算漏萃取。
- **废弃/禁用换算注记（票 34，禁用是 Owner 权柄）**：禁用词拦截面的机读真源 = GLS status
  含「禁用」（票 16），萃取**不因文档明令停用/废弃而自动升格禁用**——文档明令停用/废弃 →
  status 记「废弃（替代：X）」+ 疑点清单加一条『提请 Owner 升格禁用』；Owner 升格改 GLS
  status 后 banned-term 拦截与运行时拒答（refused_banned）自动生效。萃取侧顺手标禁用 = 越权
  下 Owner 的业务裁决，不得为之。
- owner 文档未给 →「待 Owner 确认」；relatedObjectRefs 只挂本草案真实存在的对象元素，
  无承载留空不硬挂（文档给术语不给结构承载是常态，缺的留待 Owner）。
- 同一概念多处定义或口径打架 → 疑点登记，不擅自合并取舍。

## 4. 规则萃取细则（M3，条件化的立与不立）

- **立**：条款可改写成 IF…THEN 可判定形态——条件触发型（若 X 则 Y）、超限型（超过阈值判 Z）、
  必填型（X 时 Y 不得为空/不予通过）；ruleType 按判据形态取（校验/计算/…，注册表枚举内）；
  expression 与 narrative 二选一——文档是文字条款时 narrative 占位即可，判定实现待 Owner。
- **不立**：纯叙述性条款（应加强/应推进/积极配合——无可判定条件、无阈值、无违反后果）→
  疑点清单；条款只有目标没有判据（「及时」「相关部门」「定期」类含糊限定词）→ 疑点清单，
  限定词的量化口径转成待 Owner 问题。
- inputParams 按判据要素起名与定型；**字段承载（sourceField）零对象证据时不写**——不硬指；
  值集只收文档明文（如分级档位），散落收不全的不建枚举。
- reusedBy 全空：文档无行为语义（触发/前置/状态变更缺），M2 未产文件不发明挂接。

## 5. 三落点判定树与疑点识别清单

判定树：判据齐可复述 → 草案元素候选；含糊/纯叙述性 → 疑点清单；噪声 → 明示不萃取清单（带理由）。**宁可挂起不可硬建**。

| # | 特征 | 识别信号 | 落点 |
|---|---|---|---|
| 1 | 纯叙述性条款 | 应加强/应推进/持续提升类，无条件无阈值无后果 | 疑点清单（不硬转） |
| 2 | 含糊限定词 | 「及时」「相关部门」「定期」无量化 | 疑点清单（口径转待 Owner 问题） |
| 3 | 口径冲突 | 同一概念/条款两处说法不一 | 疑点清单（不擅自合并） |
| 4 | 重复定义 | 同一术语多处定义措辞不一 | 疑点清单 |
| 5 | 状态缺失 | 涉及新旧口径但文档未声明孰废孰立 | 疑点清单（status 不臆测） |
| 6 | 引用悬空 | 条款引用了资料库中不存在的文档/条目 | 疑点清单 |

- 每条疑点四要素：锚点+原文直引+特征+待 Owner 裁决的问题；宁可多报不可漏报；
  识别清单未覆盖的可疑信号同样登记，特征名如实描述。
- 疑点同时回写证据索引疑点清单节，保证「看索引即见疑点」。

## 6. 证据等级标注

| 等级 | 含义 | 标注要求 |
|---|---|---|
| D | 定义句/条款原文直引 | 注锚点即可 |
| I | 推断（口径占位、状态归类、值集假定） | 必须标「待 Owner 确认」，归属类只进疑点清单 |

草案与证据索引头部统一声明「证据非权威，待 Owner 确认」。

## 7. 覆盖不变量（机判口径）

- **标记条目清单**：定义句/条款逐行 `编号  类型（术语/规则/叙述）  锚点`，随输入落盘——
  覆盖不变量的输入侧；清单与文档对不上，后面全部白做。
- **两落点**：草案元素（证据索引可指认 ID）/ 疑点清单（D 编号）——每条标记必须落且只落
  一处登记；标记中混入的噪声条目落明示不萃取清单（第三落点，带理由）。
- **覆盖对照表**：证据索引末节，逐条一行，是覆盖载体与探针判定面（从节标题扫到文件尾）；
  表内反引号只锚定首列编号，缺一行 = 漏覆盖 = 红——任何其他列反引号编号都会让负变体失真。
- 机判只证「没漏」，不证「萃取得对」——萃取质量人审，不进机判。

## 8. 产出与交付

- 产物两件：草案域目录（manifest.json + 有证据模型文件）、证据索引
  （落位 `docs/doc-extractor/<域>-证据索引.md`）。
- 交付前语义闸必须全过；交付说明列出全部「待 Owner 确认」项索引 + 疑点清单 + 明示不萃取清单
  （哪个模型挂豁免、缺什么、补什么可撤豁免）。
- 本 skill 只产草案：不做 git 提交、不直改已定稿本体、不替 Owner 下业务结论。
