# profile 推荐规则（onto-modeler 细则）

> 组合真源在 `ontology/schema/model-registry.json`（各模型的 profiles 字段）；本文只写判定法，不复制组合清单——注册表变了本文不用改。

## 1. 素材信号 → 应启用模型集

通读域素材，按下表收集信号（这一步只判「是否启用」，不判内容对错）：

| 素材信号 | 应启用 |
|---|---|
| 业务对象/实体/台账/主数据，及其属性、字典、聚合约束 | M1 对象模型 |
| 动作/操作/命令/查询服务（改变或读取状态） | M2 行为模型 |
| 校验/计算/派生约束，且跨属性、跨对象或被行为复用 | M3 规则模型 |
| 参与者/角色/权限/数据范围 | M5 主体模型 |
| 流程/审批/协同/任务链 | M6 流程模型 |
| 查询/报表/统计口径 | M7 查询统计与报表模型 |
| 界面/屏幕/菜单/功能点按钮 | MU UI 模型 |

只收集有素材证据的模型：「以后可能会要」不算证据。未启用模型建了文件即语义闸 L4 违规，宁缺勿滥；漏启用会在第 2 步组合核对时暴露。

## 2. 应启用集 → 最小覆盖组合

1. 记需要集 N（信号推出的模型集合）。
2. 从 `ontology/schema/model-registry.json` 读出每个候选组合覆盖的模型集；合法候选 = 覆盖 N 的组合（组合模型集 ⊇ N）。
3. 取多余模型最少的合法候选（并列取覆盖面小者）——草案不给「用不上的模型」留空文件。
4. 没有任何组合覆盖 N：素材要求超出当前注册表能力 → 停下，走元模型错路由升级 schema，不得私造组合名。
5. N 为空：不建域目录，先补素材。

## 3. 产出物格式：《profile 建议》文档

- 结论行：**建议 profile = <组合名>**。
- 启用清单表：模型 | 骨架文件 | 启用理由（必须引素材原文短语，可审计）。
- 组合核对段：写明候选组合各自覆盖什么、为何取/不取（防「拍脑袋选组合」）。
- 未启用说明段：列出不启用的模型与原因（无素材证据）。
- 待 Owner 确认段：业务判断（范围取舍、口径取舍）一律挂这里，本工序不替人定。
