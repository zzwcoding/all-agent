# 逆向指导书（db-reverse 细则）

> 全文域无关：只定义「从库表结构到本体草案」的转换规则，不含任何具体业务域知识。
> 与 schema 真源冲突时 schema 赢、回改本指导书；schema 查什么见 SKILL.md 输入输出契约中的 `ontology/schema/**`（人读总纲 + 两份机读表）。

## 1. 输入形态、采信范围与补记规则

### 1.1 输入三类

1. DDL 文件（CREATE TABLE 语句）；
2. 库连接描述（经 information_schema / SHOW CREATE TABLE 等取结构）；
3. 字段级数据字典文档（表/字段/类型/键/单位/样本行的文字版）。

### 1.2 采信范围（证据只有这些）

- 表名、列名、列类型、主键/唯一约束、外键声明；
- 表注释与列注释（含注释里的枚举值集、单位、脏特征描述）。

### 1.3 不采信

- 样本数据行本身（注释明示的脏特征除外——那是注释，采信）；
- 存储过程/触发器/视图逻辑中的业务规则（属代码逆向工序的素材）；
- 从库名/表名引申的"行业惯例"语义。

### 1.4 补记规则（输入为字典文档、信息缺口时）

- **类型补记**：字典未声明类型的列，按字段语义占位常见类型，映射证据标注「类型补记」；
- **列名补记**：字典只声明键语义（如「编号+日期」）未给列名的，按邻表同构补记列名，映射证据标注「列名补记」；
- 补记是占位不是发明——逐条留痕、逐条标待 Owner 确认；约束（外键/唯一/检查）字典没有就一个都不加。

## 2. 对象划分（保守默认）

- **一表一候选聚合根**，不做合并/拆分/提升——这些都是业务判断，结构证据不背书。
- 视图/中间表：标注为候选值对象或剔除候选，待 Owner。
- 表间同名键列：只记「疑似关联」进疑点清单，不建任何引用结构（见 §6）。

## 3. 类型映射表

| 输入类型（SQL 常见写法） | M1 属性 type |
|---|---|
| CHAR / VARCHAR / TEXT | String |
| DECIMAL / NUMERIC / NUMBER | Decimal |
| INT / INTEGER / BIGINT / SMALLINT | Integer |
| DATE | Date |
| DATETIME / TIMESTAMP | DateTime |
| BOOLEAN / BOOL / TINYINT(1) | Boolean |
| 注释给出**完整**值集的短文本 | Enum（enumValues，值逐字取注释） |
| 注释值集不全或无值集 | String + 疑点（不建枚举） |

- 位宽（VARCHAR(8)、DECIMAL(10,2)）不进属性定义，映射证据留痕即可。
- 主键自增（AUTO_INCREMENT 等）不改变映射，只进映射证据注记。
- 类型补记的列同表走映射，属性定义与原生列无差别——差别只留在映射证据的来源栏。

## 4. 命名规范化

- 列名 snake_case → 属性名 lowerCamelCase；表名 → alias 大驼峰英文标识符。
- 对象/属性中文名来源优先级：**表/列注释标题原文 > 字典小节标题 > 语义直译**；直译一律在对象清单标「待 Owner 确认」。
- 保留业务原词不做同义词改写（改写是术语工序的事，不是逆向的事）。
- ID 按模型前缀纪律生成：聚合根 `AGG-{域}-{NNN}`，三位序号按源表清单顺序稳定编发。

## 5. 主键（PK）→ 标识映射约定

- **单列主键**：照常映射为属性（保留业务列名，不强改为 id）+ `unique: true`。
- **复合主键**：成分列全部照常映射，不设属性级 unique（属性级唯一≠键整体唯一）；键构成（列序）写入聚合根描述。
- **无主键**：登记疑点；属性不设 unique；唯一性判定待 Owner。
- 非主键的唯一约束（UNIQUE 声明）→ 对应属性 `unique: true`，映射证据留痕。

## 6. 关系判定的保守边界（零证据零结构）

| 输入证据 | 可建 | 仍须 Owner 确认 |
|---|---|---|
| 外键声明（FOREIGN KEY） | AggregateRootRef 属性（targetAggregate 必填）或聚合关联；方向/基数按声明 | 关联语义、建模取舍 |
| 仅同名/同义键列，无外键 | **什么都不建**——「疑似关联」进疑点清单 | 关联是否成立 |
| 注释值集完整 | enumValues | 值的业务含义 |
| 字典表声明（输入里有独立码表结构） | data_dictionaries | 码表语义；注释值集≠字典表，不因注释建字典 |

## 7. 脏特征识别清单（识别即登记，不静默吞）

| # | 特征 | 识别信号（注释/结构） | 落点 |
|---|---|---|---|
| 1 | 单位混写 | 同列注释出现两个计量单位 | 疑点 + 草案描述点名 |
| 2 | 重复行 | 同键多行；或注释自述与主键声明冲突 | 疑点 |
| 3 | 迟到/补录 | 批次号带补录标记、注释言明补录 | 疑点 |
| 4 | 新旧编码并存 | 同一语义两套码值并存 | 疑点；值集不全不建枚举 |
| 5 | 缺失 | 注释言明缺失比例/频次不齐 | 疑点；required 不设 |
| 6 | 口径不一 | 注释言明多方算法/口径差异 | 疑点 |
| 7 | 跨期切割 | 起止跨越自然周期、注释言明归属争议 | 疑点 |
| 8 | 反规范化冗余 | 同义信息行内重复 | 疑点 |
| 9 | 状态滞后 | 注释言明状态不随事实更新 | 疑点 |
| 10 | 矛盾行 | 注释言明字段间逻辑矛盾 | 疑点 |
| 11 | 粒度不符 | 键粒度与列语义不符（如月粒度走日期列） | 疑点；粒度记入聚合根描述 |

- 每条疑点四要素：位置（表.列）+ 特征 + 输入原文证据 + 待 Owner 裁决的问题。
- 疑点同时回写草案对应对象的 description（点名属性），保证「看草案即见疑点」。
- 宁可多报不可漏报；识别清单未覆盖的可疑信号同样登记，特征名如实描述。

## 8. 证据等级标注

| 等级 | 含义 | 标注要求 |
|---|---|---|
| D | DDL 结构直证（列/类型/键/外键声明） | 映射证据注明来源列即可 |
| C | 注释/字典文字（值集、单位、脏特征） | 映射证据引用原文短语 |
| I | 推断（直译名、类型/列名补记、关联猜测） | 必须标「待 Owner 确认」，关联类只进疑点清单 |

- 映射证据文件逐条给等级；三份产物与草案头部统一声明「证据非权威，待 Owner 确认」。

## 9. 产出与交付

- 产物四件套：对象清单、映射证据、脏特征疑点清单、模型 YAML（含域 manifest.json）。
- 交付前语义闸必须全过；交付说明必须列出全部「待 Owner 确认」项的索引。
- 本 skill 只产草案：不做 git 提交、不直改已定稿本体、不替 Owner 下业务结论。
