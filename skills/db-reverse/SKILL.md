# db-reverse · 数据库逆向（L1 工序，前端适配器）

把既有库表结构（DDL）变成结构完备、能过语义闸的本体**草案**，自下而上供业务 Owner 裁决。本 skill 机器通用：正文不含任何具体业务域知识，域素材只存在于出厂集与用户提供的输入里。

## 触发面 / 何时用

- 用户要「把这个库/这份 DDL 逆向成本体」时使用。
- 不适用：从需求文档正向建模（正向建模是另一道上游工序）；改已定稿本体（写入必经 MR，本 skill 只产草案不进仓）；运行期查询口径（那是运行时服务的事）。

## 输入输出契约

- reads：用户提供的 DDL 文件或库连接描述（采信范围见 references/reverse-guide.md §1——表/列/类型/主键/外键声明/注释/注释内枚举值集）；`ontology/schema/**`（schema 文档与两份机读表：模型注册表、依赖白名单）。
- writes：`ontology/<域>/**` 草案——域 manifest.json、有证据的模型文件（逆向默认只有 M1 对象层）+ 三份工序产物：对象清单、映射证据、脏特征疑点清单。只产草案，进仓走 MR。
- 依赖脚本：`tools/schema_check.py`（语义闸，修整步的判定器）。

## 工序（按序执行，每步产物落盘）

1. **DDL/库表解析**：取表清单、列/类型/键/注释；输入是字段级字典文档而非建表语句时，按 references/reverse-guide.md §1.4 的补记规则转写（类型补记/列名补记逐条留痕）。产出《映射证据》的输入侧（逐表逐字段注源）。
2. **对象/属性抽取**：默认一表一候选聚合根；列 → 属性按类型映射表与命名规范化转换；主键按 PK→id 映射约定落（单列主键标 unique，复合主键键构成记入聚合根描述）。产出《对象清单》：源表 → 对象 ID/名/键/属性数/疑点，覆盖全部输入表。
3. **脏特征疑点清单**：按 references/reverse-guide.md §7 识别清单逐表过一遍，识别到的疑点逐条登记（位置+特征+输入原文证据+待 Owner 裁决的问题）——**不静默吞掉**，并把疑点点名回写进草案对应对象的描述。
4. **生成草案+映射证据**：按 schema 公共字段与 ID 前缀约定落模型 YAML + manifest.json（profile 取注册表组合名，默认建议最小核心组合）；引用与关联零证据零登记（无外键声明 → 不建 AggregateRootRef/聚合关联，关联推断只进疑点清单）。草案头部固定声明「证据非权威，待 Owner 确认」；《映射证据》逐字段给出「列 → 属性 + 类型 + 证据等级」。
5. **修整过语义闸**：跑 `python3 tools/schema_check.py <域目录>`，按报告逐条修复直到全过。本 skill 不做 git 提交、不直改已定稿本体。
6. **交 Owner 裁决**：交付时明示——草案与三份产物全部为证据面，对象划分/中文名直译/关系推断/口径取舍均「待 Owner 确认」；Owner 裁决后按 MR 流程进仓。

## 行为约定

- **草案头部固定声明「证据非权威，待 Owner 确认」**；交付物不得作为已定稿本体消费。
- **不发明 DDL 里不存在的业务语义**：无外键声明 → 零引用零关联；值集不全 → 不建枚举；无业务过程证据 → 不产行为/规则/流程文件；一表一对象为默认划分，合并/拆分留待 Owner。
- **疑点不静默吞掉**：识别清单命中的每一条都进疑点清单并回写草案，宁可多报不可漏报。
- **AI 只做格式转换与结构完备性**：业务语义（对象划分、口径、关系、枚举语义）必须人确认。
- 字典项/枚举项停用置 enabled: false 保留行，不删除；引用不得靠名称猜测。
