# 反问收敛规则（requirement-explorer 细则）

> 全文域无关：只定义「从粗需求到细稿三节」的收敛规则，不含任何具体业务域知识。
> 与 schema 真源冲突时 schema 赢、回改本规则；schema 查什么见 SKILL.md 输入输出契约中的
> `ontology/schema/**`（人读总纲 + 两份机读表）。映射侧（候选怎么立）见 req-to-onto-mapping.md。

## 1. 输入形态与采信范围

### 1.1 输入形态

粗需求/粗 PRD 的常见形态：背景与目标段落、业务对象罗列（粗属性）、业务规则罗列（粗约束）、
角色与流程描述（称谓级）、未提及/非目标声明。成熟度不齐是常态——正因不齐才需要反问收敛。

### 1.2 采信范围（证据只有这些）

- 正文明确写出的业务对象、属性名、值集、规则表述、角色称谓、流程动作；
- 「未提及/非目标」类声明（它们是明示不建模清单的证据来源，同样采信）；
- 【】等显式标记（输入方已标记的关键词，直接进关键词清单）。

### 1.3 不采信

- 从素材引申的「行业惯例」「别人家都这么做」；
- 素材未提的隐含需求（那是提问要解决的事，不是建模的原料）；
- 称谓的字面展开（把泛称责任方展开成具体部门 = 发明语义，只能问）。

## 2. 关键词识别（覆盖不变量的输入侧）

- 实体词：素材里被管理、被流转、被记录的「东西」——通常是名词，出现频次高、
  有属性罗列或有归属表述（「一 X 挂一 Y」）。
- 口径词：承载判定口径的词——值集词、时限词、状态词、以及素材里自造的合成词
  （「超过期限仍未完成的算 X」里的 X）。
- 标记纪律：每个识别出的关键词在关键词清单落一行（一词一行）；素材原文未标记的，
  补【】标记或注明出处位置。清单是覆盖自检与机判探针的共同输入，漏词 = 覆盖面失真。

## 3. 三落点判定树（逐关键词执行）

```
该关键词的素材表述，判据是否清晰可复述（值集/判据/粒度三有一仁）？
├─ 是 → 落【草案元素】：按映射指南立候选（对象/术语/规则候选），ID 可指认
├─ 否，且属于「信息缺但业务要」→ 落【开放问题清单】：三字段提问，等 Owner 答
└─ 否，且属于「输入自述越界」或「判别边界未给」→ 落【明示不建模清单】：带理由留痕
```

- 「判据清晰」的最低标准：能写出候选元素的判定/取值文字而不需要替业务做选择。
  需要选（选粒度、选数值、选归属）= 不清晰 = 问题。
- 「输入自述越界」：素材明写「另一套事」「本次不管」「未提及」——不是漏，是边界，
  必须显式留痕防止后人当缺口补建。
- 判别边界未给（两个近义概念分不清、概念间关系只有一句带过）：不建，转问题或留痕；
  强行区分 = 发明业务语义。
- 三个落点互斥且并集须覆盖关键词全集——这就是覆盖不变量；逐词判定结果在细稿末节
  对照表登记（词 × 落点 × 依据），对照表是覆盖的可核对面。

## 4. 问题三字段（开放问题清单的结构纪律）

每问固定三字段，缺一不可：

| 字段 | 内容要求 |
|---|---|
| 问题 | 一句可回答的问句；含糊的问（「要不要建模？」）不算问题 |
| 为什么问 | 引素材原文说明缺口在哪（哪个词含糊、缺什么判据）；不给原文依据的提问是空转 |
| 影响哪个候选元素 | 指认受影响的候选（对象/属性/规则/主体/流程候选，可含「拟挂起的某模型文件」）；指认不出候选的提问先回三落点判定 |

- 机判口径：三字段齐 + 问数一致（结构完备性进出厂集断言）；问得准不准（质量）人审，
  机判不背书。
- 合并纪律：同一缺口只问一次；两个关键词缺的是同一个判据时合并成一问，两个候选元素
  都写进第三字段。

## 5. 覆盖不变量（机判口径）

- **断言**：关键词清单中每个词，必须落在三处之一——草案元素（ID 可指认）/ 开放问题清单 /
  明示不建模清单（带理由）。三处皆无 = 未收敛，不许交付。
- **机判面**：关键词清单 ×（草案域文件全文 + 细稿两节）双向核对——词在草案域文件中
  出现 = 元素落点；词在细稿两节（开放问题清单、明示不建模清单）出现 = 问题/不建模落点；
  两处皆无 = exit 1 报词。对照表是给人看的核对面，机判不扫它（它不是落点，是登记）。
- **负例纪律**：出厂集必须带漏覆盖负变体——删掉一个词的全部落点，探针必须红；
  没有负例的覆盖断言是装饰。

## 6. 含糊表述分类（提问前的定性）

| 类 | 特征 | 典型形态 | 处置 |
|---|---|---|---|
| 时限类 | 有「及时/尽快/定期」无数值 | 「尽快完成」「定期检查」 | 问：换算成什么可判定的时限/周期，从何时刻起算 |
| 归属类 | 责任方用泛称 | 「责任单位」「有关方面」 | 问：具体部门/角色清单，是否登记处理人 |
| 粒度类 | 主体/层级只有称谓 | 按人/按岗位/按组织未定 | 问：建模粒度三选一，职责边界 |
| 判别类 | 近义概念边界未给 | 「A 和 B 是一回事吗」没说清 | 问边界；答前两者都进明示不建模或只立其一 |
| 值集类 | 枚举只给部分值 | 「等状态」 | 不建枚举（String 占位），问全集；与映射指南一致 |

- 定性的意义：问题第三字段（影响哪个候选元素）由定性直接给出——时限类影响规则候选，
  归属/粒度类影响主体候选，判别类影响对象/术语候选，值集类影响属性枚举。
- 含糊词本身不进草案结构（不立属性名、不立规则名、不进术语表），只进问题与对照表——
  探针语义下这保证「草案无该词」的负例可构造。
