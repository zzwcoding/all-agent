# 需求→本体映射指南（requirement-explorer 细则）

> 全文域无关：只定义「粗需求表述 → 本体候选元素」的转换规则，不含任何具体业务域知识。
> 收敛侧（落点判定与提问）见 questioning-guide.md；schema 字段级约束以 `ontology/schema/**`
> 为真源（人读总纲 + 模型注册表 + 依赖白名单），冲突时 schema 赢。

## 1. 三分类映射总表

| 素材形态 | 映射目标 | 立候选的最低证据 | 证据不足时 |
|---|---|---|---|
| 名词（被管理/流转/记录的「东西」） | 对象候选（M1 聚合根）；承载口径的名词→术语候选（GLS） | 有属性罗列或有归属表述 | 挂起；只进对照表 |
| 动作（做某事/推进某状态） | 行为候选（M2）；承载动作语义的名词→术语候选 | 有触发方+作用对象+状态变更语义 | 挂起，不产行为文件 |
| 约束（必须/不得/超过…算…） | 规则候选（M3）；可判定取值限制→属性级约束（required/unique/refRules） | 判据可复述（能写出判定文字而不替业务选择） | 转开放问题 |
| 值集/状态词 | 枚举（enumValues）或术语 | 值集完整 | String 占位 + 提问 |
| 主体称谓 | 主体候选（M5，通常挂起） | 粒度与职责边界明确 | 挂起 + 提问 |
| 「未提及/非目标」声明 | 明示不建模清单条目 | 原文位置可指认 | ——（这就是证据） |

映射纪律：每条候选在草案对应元素的 description 里注素材出处（位置+原文短语可指认）；
映射不出处即发明语义。出处是「AI 只做格式转换」的可审计面。

## 2. 名词 → 对象/术语

- 默认一个被管理名词 = 一个候选聚合根；合并/拆分/提升是业务判断，粗需求证据不背书——
  有合并猜想的，猜想进开放问题，不进结构。
- 粗属性罗列逐条映射为属性：`name`（语义转 camelCase）/ `label`（原文词，不做同义词改写）/
  `type`（按值集与语义占位）；「唯一」「必填」字样直译为 `unique` / `required`。
- 归属表述（「一 X 挂一 Y」「属于某 Y」）→ 引用属性（targetAggregate 指向候选对象）；
  方向/基数按原文单句直译并在 description 注明「待 Owner 确认」。再多一个字的关联
  （多对多、条件关联）都不建——粗需求给不起关系证据。
- 名词的两种落点：被管理的东西→对象候选；承载判定口径的东西→术语候选（GLS，definition
  只写素材可复述的判据，写不出的部分标待 Owner）。两者都占的（既是对象又是口径），
  对象立候选 + 术语也立，relatedObjectRefs 挂真实存在的候选对象。

## 3. 动作 → 行为候选（挂起纪律）

- 粗需求的动作几乎总是短语级（「上报」「派工」「关闭」）——触发方、前置条件、状态变更
  三件齐才够立 M2 行为元素；缺任一件 = 行为候选挂起：动作词记在相关对象的 description
  或开放问题第三字段里，**不产行为文件**。
- 挂起的机制面：manifest omittedModels 给 M2 带理由豁免条目（理由写明挂起的动作清单与
  缺什么），而不是产一个空 behaviors 文件——空壳文件过不了语义闸的结构性必填，也不该过。
- 行为候选挂起不等于动作丢失：每个挂起动作必须在细稿三节之一留痕（开放问题或对照表）。

## 4. 约束 → 规则候选（立与不立）

- **立**：判据可复述的约束——值域（「不得为负」）、时限判定（「超过某日期算逾期」）、
  完整性（「必填」→属性级 required）、唯一性（「唯一」→属性级 unique，不重复立 M3）。
  ruleType 按判据形态取（校验/计算/转换…）；表达式写 narrative 占位即可，判定实现待 Owner。
- **不立**：含糊约束（时限/归属/粒度类含糊表述）——转开放问题，收敛前无判据可立；
  依据见 questioning-guide.md §6。
- 规则与属性的分工：只依赖当前属性值的约束落属性级（refRules/required/unique），
  跨属性/跨对象/需复用的落 M3 候选——与 schema 的规则分层纪律同构。
- reusedBy 全空是常态：行为候选挂起时规则没有挂接点，不发明挂接（留待收敛后补）。

## 5. profile 选择与 omittedModels

- 默认建议注册表最小可用组合；粗需求几乎总缺行为/主体/查询统计证据，常见落法是
  「对象+规则+术语」类组合，缺的模型逐个在 manifest omittedModels 带理由豁免
  （理由=缺什么证据+挂起了哪些候选），不产空壳文件。
- 素材明写「不做界面/报表」的，对应模型豁免理由直接引原文——这是明示不建模清单的
  manifest 镜像，两处理由必须同口径。
- Owner 答复开放问题后补哪些文件：按豁免理由逐条对应，补文件=把该条豁免撤下。

## 6. 交付边界

- 本 skill 只产草案：不做 git 提交、不直改已定稿本体、不替 Owner 下业务结论。
- 交付三件：细稿（三节+对照表）、草案域目录、覆盖自检结论（逐词落点或探针输出）。
- 交付说明必须列出：全部「待 Owner 确认」项索引 + 全部挂起候选（哪个模型、缺什么、
  答哪问可补）。
