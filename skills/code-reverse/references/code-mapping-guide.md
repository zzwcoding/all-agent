# 代码结构→本体映射指南（code-reverse 细则）

> 全文域无关：只定义「从源码到本体草案与调用链素材」的转换规则，不含任何具体业务域知识。
> 与 schema 真源冲突时 schema 赢、回改本指南；schema 查什么见 SKILL.md 输入输出契约中的
> `ontology/schema/**`（人读总纲 + 两份机读表）。

## 1. 输入形态、采信范围与不采信

### 1.1 输入三类

1. 单文件/多文件源码（函数式/面向对象皆可）；
2. 代码库目录（按模块/包为界逐文件处理，跨文件调用与 import 互证）；
3. 源码片段（截取自更大代码库——覆盖清单只对片段内符号负责，跨片段引用记疑点）。

### 1.2 采信范围（证据只有这些）

- 类/接口声明、字段定义、方法签名与方法体；
- 常量定义与使用点（比较/赋值/分支）；
- 字面量集合（枚举持有类/常量组/状态码集）；
- 真实调用点（方法调用、函数调用）与 import / 类型标注。

### 1.3 不采信

- 注释里的业务叙事（注释只作 C 级佐证，不单独立元素——代码没做的事，注释说了也不算）；
- 从变量名/函数名引申的「行业惯例」语义；
- 运行环境/框架约定推断出的隐含行为。

## 2. 五类映射总表

| 代码形态 | 映射目标 | 立候选的最低证据 | 证据不足时 |
|---|---|---|---|
| 类（被管理的数据载体） | 对象候选（M1 聚合根） | 类声明+字段 | 挂起；只进对照表 |
| 字段 | 属性（M1） | 字段定义（类级声明或构造器赋值） | 只进对照表 |
| 方法（有状态改写/业务动作） | 行为素材（M2），默认挂起 | 触发主体+权限+时机三件齐才立元素 | 挂起不产行为文件，调用链留痕 |
| 常量约束 | 规则候选（M3） | 两处直证：常量定义+比较/分支使用点 | 只定义无使用→疑点 |
| 字面量集合 | 字典候选（M1 data_dictionaries） | 值集完整（持有类/常量组全量可见） | 值集不全→String 占位+疑点，不建 |
| 真实调用 | 调用链素材（映射文件） | 调用点可指认 | ——（调用永不直接立关联） |
| 字段引用他类 | 引用属性（AggregateRootRef，targetAggregate 必填） | 构造器字段/类型标注可指认 | 仅名称相似无字段证据→疑点 |

映射纪律：每条候选注源 `源码 file:line`；映射不出处即发明语义。出处是「AI 只做格式转换」的可审计面。

## 3. 类与字段细则

- **一类一候选聚合根**，不做合并/拆分/提升——这些都是业务判断，结构证据不背书。
- 纯工具类/纯函数模块不立对象候选：有承载业务状态的字段才立；拿不准的进明示不逆向清单或疑点。
- 构造器必填参数→属性 required；有缺省值→不标 required；**唯一性：源码无唯一性约束声明不标 unique**，登记疑点待 Owner。
- 属性名 lowerCamelCase 直译；类型按字面/使用点占位（无类型注解=使用点推断，I 级标待 Owner）。
- 字段引用他类→AggregateRootRef，方向/基数按字段直译；从方法调用或命名相似引申的关联一律进疑点清单，不进结构。

## 4. 常量约束→规则候选（立与不立）

- **立**：常量定义+比较/分支使用点两处直证——上限/下限/封顶/阈值类判定；ruleType 按判据形态取（校验/计算/…）；表达式 narrative 占位即可，判定实现待 Owner。
- **不立**：只有常量定义、无使用点（死常量→疑点）；常量只作展示文案/配置值、无判定语义（进明示不逆向清单）。
- 规则入参：方法入参非持久属性的，不编 sourceField；口径来源源码没给就写「待 Owner 确认」——入参怎么来是业务口径，不是代码事实。

## 5. 字面量集→字典

- 持有类/常量组全量值可见→M1 data_dictionaries（DICT-）：code=存储值逐字直译（D 级）、label=直译（I 级待 Owner）；状态属性落 DictionaryRef 指向该字典。
- 值集散落多处收不全→不建字典，属性 String 占位+疑点。
- 硬编码字面量比较（无集合载体）→逐值登记疑点，不臆测全集。

## 6. 调用图→行为与关系素材的保守边界

- 调用链逐跳注源：调用方（文件:行）→ 被调方（声明 文件:行；调用点 文件:行）；跨文件调用与 import/类型标注互证。
- 孤儿（零调用点）公开方法→疑点登记；不发明调用方，也不因孤儿删除素材。
- **调用链不产生对象间关联推断**（红线）：关联只从字段引用来；调用素材是行为收敛的原料——行为元素默认挂起（见 §2 方法行），ownerEntity/权限/时机齐了才转正。

## 7. 疑点识别清单（识别即登记，不静默吞）

| # | 特征 | 识别信号 | 落点 |
|---|---|---|---|
| 1 | 声明/写入分离 | 一个类的字段在另一处被直接写 | 疑点；按写入点立候选（I 级） |
| 2 | 唯一性无声明 | 标识符命名但无唯一约束 | 疑点；unique 不标 |
| 3 | 孤儿方法 | 公开方法全库零调用点 | 疑点；调用链留痕 |
| 4 | 类型未注解 | 字段/参数无类型标注 | 疑点；按使用点占位（I 级） |
| 5 | 判定缺口 | 状态/常量未参与看似相关的判定 | 疑点 |
| 6 | 死常量 | 定义后无任何使用点 | 疑点 |
| 7 | 值集不全 | 字面量散落多处收不全 | 疑点；不建字典/枚举 |

- 每条疑点四要素：位置（文件:行）+ 特征 + 源码证据 + 待 Owner 裁决的问题。
- 疑点同时回写草案对应对象的 description，保证「看草案即见疑点」。
- 宁可多报不可漏报；识别清单未覆盖的可疑信号同样登记，特征名如实描述。

## 8. 证据等级标注

| 等级 | 含义 | 标注要求 |
|---|---|---|
| D | 源码结构直证（类/字段/常量/字面量/调用点） | 注 file:line 即可 |
| C | 注释文字 | 引原文短语 |
| I | 推断（类型占位、label 直译、声明/写入归属） | 必须标「待 Owner 确认」，关联类只进疑点清单 |

- 映射文件逐条给等级；草案与映射文件头部统一声明「证据非权威，待 Owner 确认」。

## 9. 符号覆盖不变量（机判口径）

- **符号清单**：公开符号逐行 `符号 文件:行 素材类别`（字段/方法随类以点号登记），随输入落盘——覆盖不变量的输入侧；清单与代码对不上，后面全部白做。
- **三落点**：草案元素（对照表可指认 ID）/ 疑点清单（D 编号）/ 明示不逆向清单（带理由）——每符号必须落且只落一处登记。
- **对照表**：映射文件末节，逐符号一行，是覆盖载体与探针判定面（从节标题扫到文件尾）；表内反引号只锚定首列符号名，缺一行=漏覆盖=红。
- 机判只证「没漏」，不证「映射得对」——映射质量人审，不进机判。

## 10. 产出与交付

- 产物两件：草案域目录（manifest.json + 有证据模型文件）、调用链素材映射文件。
- 交付前语义闸必须全过；交付说明列出全部「待 Owner 确认」项索引 + 全部挂起候选（哪个模型、缺什么、补什么可撤豁免）。
- 本 skill 只产草案：不做 git 提交、不直改已定稿本体、不替 Owner 下业务结论。
