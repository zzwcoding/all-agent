# impact-analyzer · 变更影响分析器（工序，治理/输出两用）

回答「改 X 会影响什么」：对本体变更做**只读、机械取证、可复现**的影响分析——影响链每条带传播依据（哪条 ref 字段），落地顺序给到可执行；无下游引用时明确报「无影响」。本 skill 机器通用：正文不含任何具体业务域知识，域知识只存在于本体仓。

## 触发面 / 何时用

- 用户要「改 X 会影响什么」「评估这个变更」时使用。
- 不适用：建本体/加模型元素（本体建模工序的事）；查口径/问业务对象（运行时语义服务的事）；把变更落进仓（写入必经 MR + 语义 CI，本 skill 只产报告不产草案）。

## 输入输出契约

- reads：`ontology/**`——经 `tools/graph_index.py` 建图检索；传播方向的机读真源是 `ontology/schema/model-deps.json` 依赖白名单（ref 字段从引用方指向被依赖方）。
- writes：`docs/impact/` 下的影响分析报告——**报告是唯一产物，本 skill 不改任何本体文件**（只读仓；改本体走 MR + 语义 CI）。
- 依赖脚本：`tools/graph_index.py`（`--query` 存在性确认 / `--impact` 反向影响集 / `--json` 机读输出）。

## 工序（固定变更 → 机械取证 → 影响链 → 落地顺序 → 特例纪律 → 报告落盘，顺序固定）

1. **固定变更**：把「改 X」落成变更描述（元素 ID + 改什么）；`--query` 确认 ID 存在，不存在明确报「未找到」不猜、不做名称近似匹配。
2. **机械取证**：`tools/graph_index.py <ontology目录> --query <ID> --impact` 沿依赖边反向走到底，得到受影响节点集；**逐条记录 via=<ref字段名> 与 path=传播链——这就是传播依据**，没有 via 的影响项不出口。
3. **影响链表**：每行 = 受影响 ID / 模型 / 跳数 / 传播依据（via 哪条 ref）/ 建议落地顺序位次；格式照 `docs/impact/` 报告模板（references/report-template.md）。
4. **建议落地顺序**：先改被依赖者，后改依赖者（判定规则见 references/rollout-order.md）——主序取跳数升序，方向依据 model-deps.json 依赖白名单的 ref 方向；字典项作为取值域被依赖方先行，查询出口与界面等消费末端最后。
5. **特例纪律**（处置细则见 references/special-cases.md）：字典项——停用不删除、必须扫描引用方给停用影响；无下游引用——明确报「无影响」并列核验方式，不硬凑。
6. **报告落盘**：落 `docs/impact/NN-*.md`，NN 取两位序号递增（扫 `docs/impact/` 现有最大号 +1，无报告时从 01 起）；报告头部固定取证命令与图统计，保证任何人重跑命令得到同一影响集。

## 行为约定

- **每条影响项必须带传播依据**：影响链每行标注 via=<ref字段名>（机械取证直接产物），无依据的影响项不出口、不脑补传播路径。
- **只读仓**：本 skill 不改任何本体文件，报告是唯一产物。
- **可复现**：报告附取证命令原文 + 图统计（节点数/边数/影响集规模），机器结论与命令输出一一对应。
- **不硬凑**：零命中就是零命中，报「无影响」并给核验方式；不为"显得全面"列无依据的节点。

## 细则索引（进入对应步骤时读）

- references/report-template.md——`docs/impact/` 报告模板（头部元信息/影响链/建议落地顺序/特例处置/边界说明，节结构必备）
- references/rollout-order.md——落地顺序判定规则（跳数主序 + 依赖方向微调 + 字典先行/消费末端收尾）
- references/special-cases.md——特例处置（字典项：停用不删除 + 引用扫描；无下游引用：明确报无影响 + 核验方式）

## 出厂集（Seam）

`fixtures/impact-analyzer/`——固定变更输入清单三场景（改对象字段/停用字典项/改无下游对象）→ 断言参照报告：影响链覆盖全部直接引用者、含建议落地顺序、字典「停用不删除」纪律与引用扫描、无影响场景零硬凑（守卫正则禁现受影响 ID 列表），另附 --impact 机读佐证。改本 skill 工序描述前，先确认出厂集仍绿。
