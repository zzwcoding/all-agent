# 落地顺序判定规则

原则: **先改被依赖者，后改依赖者**。方向真源 = `ontology/schema/model-deps.json` 依赖白名单（edges: from 模型 × ref 字段 → to 模型集；ref 字段从引用方指向被依赖方，被指向者是被依赖方）。`tools/graph_index.py --impact` 的输出顺序即按此方向的反向 BFS 首达序。

## 判定（两级）

1. **主序 = --impact 跳数升序**：跳数小者离被改对象近（反向 BFS 首达即最少跳），先感知先落地。
2. **同跳数微调 = 依赖方向**：被依赖方在前。经验层序（与依赖白名单 edges 方向一致，从被依赖到依赖）: 数据结构（对象/字典/关联）→ 规则 → 行为 → 权限角色 → 流程 → 查询出口 → 界面。
3. **层序与跳数冲突时以跳数为准**：依赖白名单存在类型级互指（如权限↔行为经 targetRef/requiredPermissions 双向），层序只是启发式，不许用它推翻跳数主序。

## 固定位次

- **顺序 1 = 变更对象本体**（若本体自身也要改）：一切 ref 的汇聚点，最被依赖。
- **字典项场景：字典先行**——数据字典是取值域被依赖方，多个对象字段共指，字典项翻转先于一切引用方适配。
- **查询出口与界面最后**：消费末端，展示/取数面的适配放收尾（它们不受数据结构就绪与否的阻塞）。

## 输出形式

报告中「建议落地顺序」节 = 原则一句话 + 有序列表（`顺序 N — 元素/组（一句理由）`）；影响链每行的「顺序 <k>」位次与本节列表严格一致。理由只写依赖方向事实（via 哪条 ref、经谁传导），不写工作量估计。
