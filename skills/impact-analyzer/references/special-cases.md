# 特例处置 · 字典项与无下游引用

两类特例机械面覆盖不到或覆盖为空，处置纪律固定如下；命中与否都以报告「特例处置」节显式记录（命中写处置，未命中写「本场景未命中特例」）。

## 字典项（改/停用字典项）

- **纪律: 停用不删除**——字典项只能置 enabled=false，不删 code。存量数据与历史单据可能仍携带该 code，删除即历史口径失真；停用仅关新单据的可选性。
- **机械面**: 图索引只沿元素 ID 的 ref 字段建边；字典项 code 不是元素 ID，不进图。取证 = 对字典 ID 跑 `tools/graph_index.py --impact`，得经 dictionaryId 等直接引用方与全链（每行带 via）。
- **人工补充扫描（必须做，不静默吞掉）**: 引用该字典的对象字段取值域使用面 + 文字语义依赖（如行为前置条件/规则表达式以文字提及某取值）。发现即写入报告并标「待 Owner 确认」——这是本 skill 唯一允许的非机器结论，且必须显式标注。
- **落地顺序**: 字典先行（取值域被依赖方），直接引用字段的对象次之，再沿影响链外推（见 rollout-order.md）。

## 无下游引用（--impact 零命中）

- **结论措辞**: 「无影响——仓内没有任何 ref 字段指向该对象（无下游引用）」，写在影响链节首位，影响链保持零行。
- **核验方式必须给全**: 取证命令原文 + 人类读输出「0 个受影响节点（沿依赖反向走）」+ 机读形态影响集为空数组 + 图统计对照（全图节点/边数）。四者齐才算"核验过"，缺一个都是口头结论。
- **不硬凑**: 不列任何受影响 ID、不写"可能影响某某"；影响链零行是本结论的正确形态，不是偷懒。
- **边界声明必须带**: 机械面只覆盖 ID ref 通道，「无影响」指 ref 通道无下游；语义约定/治理面关系不在机器结论范围内，需要时转人工评估。
