# 报告模板 · docs/impact/ 下的影响分析报告

报告 = 本 skill 的唯一产物。规范样例见出厂集 `fixtures/impact-analyzer/` 的 expected-output/（三场景各一份，同时是出厂集断言的锚点）。全部节为必备：无影响场景的影响链节写「无影响」结论与核验方式（见 special-cases.md），不删节。

## 节结构与填写规则

```markdown
# 影响分析报告 NN · <一句话变更描述>

- 变更对象: <元素ID>（<模型> · 域 <域名>）
- 变更内容: <改什么>
- 取证命令: python3 tools/graph_index.py <ontology目录> --query <ID> --impact
- 图统计: 节点=<N> 边=<M>；影响集 <K> 个受影响节点（沿依赖反向走）

## 影响链（每行=受影响 ID / 模型 / 跳数 / 传播依据 / 建议落地顺序）

- <受影响ID>（<模型>）hops=<n> via=<ref字段名>（path: <传播链>）｜顺序 <k>

## 建议落地顺序（被依赖者优先）

原则: 先改被依赖者，后改依赖者（方向依据依赖白名单 ref 方向）。
1. 顺序 1 — <变更对象本体或被依赖核心>（<一句理由>）
2. …

## 特例处置（如命中）

- <字典项/无下游引用的处置记录；未命中写「本场景未命中特例」>

## 边界说明

- 只读仓声明 + 机械面边界（ID ref 通道之外须人工复核的点，标「待 Owner 确认」）
```

## 填写规则

- **NN 编号**：两位序号递增，扫描 `docs/impact/` 现有最大号 +1，目录为空从 01 起；一份分析一份报告，文件名 = `NN-<变更对象小写短名>-<变更要点>.md`。
- **影响链行五要素缺一不可**：受影响 ID、模型、跳数、via=<ref字段名>、顺序位次；via 缺失的影响行不许出现（spec 行为约定）。
- **取证命令与图统计照 --impact 输出原文抄录**：人类读形态的「影响集: K 个受影响节点」、图统计「节点=N 边=M」直接对抄，保证可复现。
- **顺序位次一致**：影响链行的「顺序 <k>」必须与「建议落地顺序」节的有序列表一致（判定规则见 rollout-order.md）。
- **跳数=0 的变更对象本体不进影响链**（影响链只收受影响方），本体写进头部「变更对象」并占建议落地顺序的顺序 1。
